keystonev2 as a Misskey/Sharkey replacement — admin / backend / power-niche audit
1. Verdict + coverage
Verdict: not an admin replacement at all; a solid non-admin client data-layer with real gaps in backend edge cases.
Surface	Coverage (approx.)	One-line verdict
Admin console / moderation backend	0% — no admin/* call exists anywhere in v2	Nothing attempted; by design a client, but there is not even read-only queue/meta surfacing
Backend / data-layer (non-admin Misskey API)	~65% of the everyday surface; ~35% of the full non-admin surface	Timelines, post/renote/reaction, mutes, clips, antennas, lists, drive-basic, drafts, scheduling, translate all wired; drive-advanced, channels/chats/messaging, announcements, roles, import-shape are missing or wrong
Power-niche (Sharkey/Catodon/Pinetree divergences, quotes, emoji)	~55%	Flavor detection + like-shortcut + quote-refusal + ffVisibility + remote-post resolution exist; Sharkey bubble/TMF/sensitive-words, emoji license/steal, batch ops, channel/chat, follow-request batch, antenna exclusion-hosts do not
The v2 transport discipline itself is good (per-origin token binding, origin guard, 204/404 handling). The failures are all omission or wrong-shape, not architecture.

3. Top 10 backend-correctness risks
 1. Import shape is wrong — imports will fail. v2 sends {file: <raw text>} (importExport.ts:36-51); upstream requires {fileId} of a Drive upload (i/import-following.ts:52-59). Fix: upload-then-fileId, mirroring the official client.
 2. Export treated as synchronous. Upstream i/export-notes only enqueues (createExportNotesJob, 1/day limit); v2 awaits a payload (importExport.ts:63-84). Needs job/notification completion handling or at minimum the rate-limit surfacing.
 3. like: unsupported seeded by flavor label, never probed. backend.ts:220 + seedLikeSupport(origin, false) means any Misskey-flavored server that backports notes/like never gets it (like.ts:57-80 throws before touching the wire). Presence should be probed once per origin, not assumed from the label.
 4. No Misskey-side scope-upgrade path. scopeHealth short-circuits Misskey to misskey-no-scopes (store.ts:447-457); sessions minted before a KEYSTONE_PERMISSIONS addition (auth.ts:107-128) hit 403 PERMISSION_DENIED (client.ts:288-296) with only per-screen handling (Clips.tsx:241). Needs a global stale-permission prompt.
 5. Drive uploads always land in root. upload() sends no folderId/force (client.ts upload vs upstream drive/files/create.ts:78-82). Drive screen + composer both affected.
 6. notes/edit drops noQuote/poll edits. EditNoteParams carries only text/cw/visibility/visibleUserIds/localOnly/fileIds (noteEdit.ts:13-23) while create supports noQuote + poll — edits silently drop quote-refusal and can't touch polls.
 7. Scheduled/server-draft lists are untilId-only (schedule.ts:20-30, serverDrafts.ts:19-29) — no sinceId, so pull-to-refresh/new-arrival checks can't page forward; every other timeline supports both (adapt.ts:432-454).
 8. Dead declared surface: AnnouncementsApi + ChannelsApi. Declared in core/backend.ts:514-528, never implemented in misskey/backend.ts (zero hits). Either implement (announcements are public, low-cost) or delete so capability-gating audits stop passing over corpses.
 9. Messaging/chat entirely absent but undetectable. No chats/messaging wire, and stream.ts channelSpec has no messaging branch — DMs are silently unavailable rather than gated with a reason. At minimum needs the chats: unsupported gate surfaced where messages UI would live.
10. External (third-party) path bypasses the origin guard by design but has no host allowlist. postDirect POSTs to any scheme://host (external.ts:156-231); combined with externalApiCall injecting i: token, a confused/malicious host string sends the token anywhere. Sessions are correctly isolated for the primary path — this is only the external-account path, but it deserves an explicit host-confirmation step (it has one in UI flow — keep it).
4. What is needed for an admin-usable Misskey replacement
In order, smallest-first:
1. Read-only server insight (1 slice): admin/server-info, admin/meta, admin/queue/stats, get-online-users-count, meta policy fields surfaced in a SysDebug-style screen. Proves the admin/* credential path (role-gated token, 403 handling) without any mutating endpoint.
2. Announcements read + federation read (1 slice): implement the already-declared AnnouncementsApi (announcements list) and add federated-instances/list + show-instance to the existing Network.tsx screen. Closes two dead/missing read paths.
3. Reports queue (1–2 slices): admin/abuse-user-reports + resolve/update/forward-abuse-user-report + notification-recipients. This is the daily-driver moderation surface; upstream abuses.vue is the spec.
4. User moderation (1–2 slices): admin/show-user(s), suspend/unsuspend-user, update-user-note, show-moderation-logs, reset-password. Role-gate the whole section on isAdmin/isModerator from i (currently never read for role flags).
5. Roles + emoji admin (2 slices): admin/roles/* (list/show/users/assign/unassign at minimum; policy editor is large — defer), admin/emoji/* read + add/update/delete + copy (steal) + license fields. This also fixes the §2c emoji-license gap.
6. Instance/federation management (later): admin/federation/update-instance, relays, update-meta, block/silence hosts, sensitive-words. Needs design care (destructive, needs confirm + audit-log surfacing via show-moderation-logs).
7. Backend corrections first regardless: fix import fileId shape (#1), export job handling (#2), upload folderId (#5), edit noQuote (#6) — all four are user-facing data-loss/wrong-behavior bugs, cheaper than any admin slice.
Explicit non-goal confirmation: queue-job manipulation (clear/promote/retry/remove-job), delete-account, delete-all-files-of-a-user, and reset-db should stay out of a mobile client even long-term; link to the web admin console instead.
