Keystone v2 visual/UI + cross-cutting audit
1. Verdict + polish %
Verdict: strong single-column reader/composer, not yet a Mastodon/Misskey replacement. The butterfly shell, feed read path, composer, RichText, and settings tree are real and well-tested. The deck (tarantula) and widgets are explicitly unbuilt, theming is one grey pair with no accent/terminal/OLED, push is absent, and roughly half the settings surface is honest placeholders. Nothing observed fakes data — the honest-disabled pattern holds — but "honest placeholder" is still placeholder.
Polish: ~55–60% of a visual replacement. Breakdown: shell/nav 85%, theming 35%, deck/widgets 5%, composer+media UX 80%, RichText 90%, i18n 55%, a11y 60%, responsive 80%, notifications UX 65% (no push), settings 50%, empty/loading/error 90%, perf cues 45%.
Scope note: plan Phase 5 (deck/widgets) and fine polish (Phase 6 long tail) are unscheduled by design (rn-rebuild-plan.md §5, ADR-0002) — so several "blockers" below are known roadmap, recorded here for completeness.

3. Top visual blockers to feeling like a real replacement
1. No deck, no widgets — the defining Misskey/TweetDeck surface is absent; right rail is a literal stub string (Navigation.tsx:752). FeedDescriptor covers feeds but lacks a notifications column kind and divider that Misskey decks have. (Known: Phase 5.)
2. One theme pair, no terminal/OLED/accent — v1 ships keystone-terminal.css (gold accents, square corners, solarized palette) with zero v2 consumer; Theme/Palette/Font settings rows are placeholders. Dark grey #111 is not OLED black.
3. No push notifications — badge counts are in-app cache only; nothing registers for APNs/FCM, no background sync. Mastodon/Misskey mobile users will notice immediately.
4. No density control — text-size scales prose only; no comfortable/compact switch like Mastodon's advanced UI; v1 .compact styles unported.
5. Composer has no formatting toolbar — Mastodon has bold/italic/code/spoiler buttons and a sensitive-media toggle at compose time; v2 compose marks media sensitive only post-hoc via Drive. MFM users get raw-text entry with autocomplete only.
6. Import/export entirely placeholder — 12 rows, all disabled (TransferSections.tsx); file picker/sharing deps absent by build constraint (DECISIONS W7). Data portability is a real gap vs both references.
7. News tab is title-only rows (Explore.tsx:102-110 — title/provider/description, no images, no "load more" polish beyond a button); trending-users/tags are bare rows without avatars/follow buttons, unlike Mastodon explore cards.
4. Niche polish gaps
- Reduce-motion/autoplay: reduced-motion kills popup/lightbox fade only (motion.ts); MFM motion renders static (documented). No autoplay setting for gifv/video — VideoTile/LightboxVideo autoplay on open with no user control; no "sensitive media defaults" setting beyond per-post CW veil.
- Unread badges: in-app only, dot-vs-pill variants exist (Navigation.tsx:348-363); no app-icon badge, no per-column unread (deck N/A).
- Obscure widgets: Misskey has ~30 (BirthdayFollowings, JobQueue, Federation, Clicker, AiScript…); v2 registry doesn't exist, so even the easy ones (clock, memo, trends) aren't started. Plan §5.7 lists first five.
- Theme edge cases: overlayChrome scrim is the only sanctioned non-palette color (good); but PostCard CW box borderStrong inverts harshly, avatar fallbacks use initial-letter boxes with no identicon, and PendingEmoji 16px boxes are fine but reaction chips render literal :code: when stores fail (honest, but visually raw).
- Menu dead-ends done right but visible: menuModel.ts:146-162 — Copy RSS / Search notes / Memo / Add-to-list / Add-to-antenna / Notify / DM / Refresh remote are all LATER(...) disabled rows; the menu is long with disabled entries where Mastodon/Misskey would have working items.
- Post menu on Mastodon: clip row honestly disabled; bookmark label flips per family — good; but write:reports scope deliberately omitted (DECISIONS WS-D), so granular-token reports toast-fail.
- Explore keyboard: suggestion popup activeIndex={0} hardcoded (Explore.tsx:697) — keyboard navigation is stubbed, not wired.
- Offline: no offline banner, no queued-action indicator beyond per-action toasts; streaming reconnect badge exists (StreamBadge) but paging-only feeds are silent.
- i18n long tail: 466/548 fr entries untranslated (mostly new strings); zh-TW/yue-HK/hi catalogs exist but equally partial; localeErrors covers only coded failures, fedi gate reasons stay English (documented, fedi is Lingui-free).
- Small toggles present and correct: quote-policy conceal (onlyAuthorizedQuotes), Data Saver, plain-text content mode, like-emoji + server persist, unicode group pin/hide, feed tab prefs, per-type notification receive config (Misskey) — this is the strongest niche area; all real, all tested.
- Bubble tab: deliberately absent (DECISIONS W8/Q3 — no verifiable Bubble endpoint); correct call, but Akkoma users lose a timeline they have on other clients.
- Perf: no getItemLayout, no list virtualization tuning, no image priority/placeholder, videos instantiate players per tile; fine at current scale, will show on long media-heavy feeds on the Oppo (Phase 7.5 unmeasured).
