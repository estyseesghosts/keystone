# i18n conventions

English is the source locale. No non-English text is hand-written; carried
locales seed from the v1 reference dicts and fill in via the normal
translation flow (Wave 9 owns the sweep, X9.5 the formatters).

## Authoring (enforceable, lint-backed)

- `msg` for message descriptors, `t` inside components via `useLingui`,
  `Trans` for rich text with inline markup.
- `plural` / `select` for counts and gender. Never `n === 1 ? '' : 's'`.
- No string concatenation across message boundaries: one descriptor per
  complete sentence, with named placeholders.
- Ambiguous words carry `context:` and a translator `comment:`.
- Dates, numbers, and file sizes use the shared locale-aware formatters
  (built in X9.5); never hand-rolled `toLocaleString` options or unit
  suffixes in literals.
- Never translate server-supplied data (post text, instance names, user
  input). It renders as-is.
- `packages/fedi` returns error codes and params only, never display text
  (see X9.7). UI layers map codes to messages.

## Ratchet: no new literals

`keystone/no-literal-ui-string` (error in `src/`) reports JSX text with a
letter outside `<Trans>`, literals in speakable JSX props (`label`,
`title`, `placeholder`, `accessibility*`, `aria-label`, `alt`, `tooltip`,
`disabledReason`, `emptyText`, `description`, `headerTitle`, `subtitle`,
`caption`), and first-argument literals to `showToast` / `toastError` /
`Alert.alert` / `confirm`. Allowed: `msg` / `t` / `i18n._()` / `plural()` /
`<Trans>`, `testID`, `key`, `style`, URLs, icon names, enum comparisons.

`lint-rules/baselines/no-literal-ui-string.json` grandfathers the Wave 9
starting point per file. A file at or below its count passes; above it (or
a new file with any violation) fails. `pnpm lint:i18n-baseline` rewrites
the baseline downward only and refuses to raise it — this file is the Wave
9 burn-down meter.

## Pseudo-locale

`lingui.config.ts` sets `pseudoLocale: 'pseudo'` (also listed in `locales`
so `lingui compile` generates it; never add it to `SUPPORTED_LOCALES` or
the production picker). In dev only: `?locale=pseudo` on web, or the
dev-only storage flag on native (`setPseudoLocaleEnabled`). Anything that
still shows plain English under pseudo is an untranslated literal. The
catalog appears after `pnpm intl:compile`; before that, activation is a
safe no-op.

## Missing translations

A message missing from a non-`en` catalog falls back to the English source
message, never to the message id (pinned by a test in
`src/locale/locale.test.ts`).
