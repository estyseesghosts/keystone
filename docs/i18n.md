# i18n conventions

English is the source locale. No non-English text is hand-written; carried
locales seed from the v1 reference dicts and fill in via the normal
translation flow (Wave 9 owns the sweep, X9.5 the formatters).

## Authoring (enforceable, lint-backed)

- `msg` for message descriptors, `t` inside components via `useLingui`,
  `Trans` for rich text with inline markup.
- `plural` / `select` for counts and gender. Never `n === 1 ? '' : 's'`.
- No string concatenation across message boundaries: one descriptor per
  complete sentence, with named placeholders.
- Ambiguous words carry `context:` and a translator `comment:`.
- Dates, numbers, and file sizes use the shared locale-aware formatters
  (built in X9.5); never hand-rolled `toLocaleString` options or unit
  suffixes in literals.
- Never translate server-supplied data (post text, instance names, user
  input). It renders as-is.
- `packages/fedi` returns error codes and params only, never display text
  (see X9.7). UI layers map codes to messages.

## Ratchet: no new literals

`keystone/no-literal-ui-string` (error in `src/`, no options, no baseline)
reports JSX text with a letter outside `<Trans>`, literals in speakable JSX
props (`label`, `title`, `placeholder`, `accessibility*`, `aria-label`,
`alt`, `tooltip`, `disabledReason`, `emptyText`, `description`,
`headerTitle`, `subtitle`, `caption`), and first-argument literals to
`showToast` / `toastError` / `Alert.alert` / `confirm`. Allowed: `msg` /
`t` / `i18n._()` / `plural()` / `<Trans>`, `testID`, `key`, `style`, URLs,
icon names, enum comparisons. Every violation fails lint — there is no
grandfather file (Wave 9 burned the baseline to zero; X9.8 deleted the
`lint-rules/baselines/no-literal-ui-string.json` mechanism and the
`lint:i18n-baseline` script).

What the rule cannot see, the pseudo-locale smoke test catches:
`src/locale/pseudo-locale-smoke.test.tsx` renders the smoke screens with
the `pseudo` locale active and fails on any rendered text node matching
`/^[A-Za-z][A-Za-z ,.'-]+$/`. Error paths that only surface through
`setError` / `errorText` fallbacks and data-layer reason strings are
covered there, not here.

## Pseudo-locale

`lingui.config.ts` sets `pseudoLocale: 'pseudo'` (also listed in `locales`
so `lingui compile` generates it; never add it to `SUPPORTED_LOCALES` or
the production picker). In dev only: `?locale=pseudo` on web, or the
dev-only storage flag on native (`setPseudoLocaleEnabled`). Anything that
still shows plain English under pseudo is an untranslated literal. The
catalog appears after `pnpm intl:compile`; before that, activation is a
safe no-op.

## Missing translations

A message missing from a non-`en` catalog falls back to the English source
message, never to the message id (pinned by a test in
`src/locale/locale.test.ts`).

## Adding a string (checklist)

1. One descriptor per complete sentence, evaluated at render/call time —
   never module-level `t` / `i18n._` (it would freeze the boot locale).
2. `msg` for descriptors, `t` inside components via `useLingui` (or the
   app singleton `i18n` from `#/locale/i18n` in shared chrome), `Trans`
   for rich text with inline markup, `plural` / `select` for counts and
   gender — never `n === 1 ? '' : 's'`, never string concatenation across
   message boundaries (named placeholders instead).
3. Ambiguous words carry `context:` and a translator `comment:` (follow
   the `msg({message, context, comment})` precedent in
   `src/screens/Drive/`, `FollowRequests.tsx`, `Pagehead.tsx`).
4. Dates, numbers, and file sizes go through the shared locale-aware
   formatters (`formatCount`, `formatCompactCount`, `localeTag` in
   `src/locale/i18n.ts`); never hand-rolled `toLocaleString` options or
   unit suffixes in literals.
5. Never translate server-supplied data (post text, instance names, user
   input, file names, mime values) — it renders as-is or as a named
   placeholder value, never as message text.
6. `packages/fedi` returns error codes and params only, never display
   text; UI layers map codes through `src/lib/localeErrors.ts`
   (`formatFediError` / `toCodedError` / `errorText` with a translated
   `i18n._(msg`…`)` fallback — never a raw-string fallback, never
   `err.message`).
7. Run `pnpm intl:extract` (coordinator owns the catalogs — never
   hand-edit `src/locale/*`) and confirm the new msgid appears in
   `src/locale/locales/en/messages.po` with no diff left over.
8. Check the string under the pseudo-locale (`?locale=pseudo` on web, or
   the dev-only native flag): anything still plain English is a missed
   literal — route it through Lingui.

## Intentionally untranslated locales

English (`en`) is the only finished catalog. Everything else ships
untranslated on purpose (owner decision: no translation work in this
program) and falls back to the English source message per locale:

- `fr`, `de`, `zh-CN`, `zh-TW`, `yue-HK`, `ja`, `hi` — the 7 carried
  Keystone locales in `SUPPORTED_LOCALES` (`src/locale/i18n.ts`). Their
  catalogs seed from the v1 reference dicts where a matching id exists;
  every other entry renders the English source until a later locale pass.
- `pseudo` — dev-only rehearsal locale (never in `SUPPORTED_LOCALES`,
  never in the production picker). Its catalog is generated by
  `pnpm intl:compile` and exists only to expose untranslated literals.

A future translator starts here: pick a locale above, fill its
`src/locale/locales/<code>/messages.po` through the normal translation
flow, and re-run `pnpm intl:compile`. Do not hand-write non-English text
into `src/` outside those catalogs.
