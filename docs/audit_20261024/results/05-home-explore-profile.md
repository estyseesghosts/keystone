## Suspected bugs (file:line)

- **B1 (session-scoping, the audit's main find). `PostCard.tsx:1182` + `PostCard.tsx:1132`** — `PostCardView` renders `<ReactionChips>` **without** `sessionId`/`authorHost` and `<PostQuote>` **without** `sessionId`, although both components accept those props for the WS-C remote-emoji fallback. Both fall back to `useOptionalActiveSession()` (`ReactionChips.tsx:117`, `PostQuote.tsx:195`). In a multi-account deck column (session B card while session A is active), remote `:code@host:` emoji in chips/quotes resolves through the **wrong session's** emoji tables. Fix: thread `sessionId={sessionId} authorHost={effective.author.host}` into both call sites (2 lines each). `PostQuote` internally passes `sid` to `NestedQuote`/body `RichText`, so the one prop fixes the whole subtree.
- **B2 (stale closure). `Explore.tsx:600-615`** — `NewsTab.loadMore` closes over `links`/`cursor` state (`const seen = new Set(links.map(...))`). Two rapid `onEndReached` fires (threshold 2.0, no `useCallback`/in-flight ref beyond the `loading` flag set in the same tick) can fetch the same cursor twice and append duplicates. Also the load-more failure path (`Explore.tsx:611`) sets `error`, but the error UI only renders when `links.length === 0` (`Explore.tsx:585`) — **a load-more failure with existing items is silently swallowed** with no retry. Fix: functional `setLinks` with dedupe inside the updater, and surface `error` as a footer retry when `links.length > 0`.
- **B3 (descriptor injection inconsistency). `Tag.tsx:212`** — `TagScreen` builds `` `tag|${tag}` `` from the raw route param with no `|` sanitization, while `Explore.tsx:59` has `safeDescriptorArg` and uses it in `TagsTab`/`PostsTab`. A tag containing `|` would parse as a multi-segment descriptor. Fix: reuse `safeDescriptorArg` (export it from a shared module) in `TagScreen`.
- **B4 (429 rendered as deleted/missing). `Note.tsx:485-495`** — thread error path shows "It may be deleted, private, or on an unreachable server" for **all** errors including 429. `User.tsx:140` already special-cases 429 ("Rate limited by the server…"). Fix: mirror the `ApiError status === 429` branch in `NoteScreen` (and consider `FeedView`'s `feed.isError && !hasData` path, `HomeFeed.tsx:299`).
- **B5 (profile tab sticks across profiles). `User.tsx:70`** — `tab` state (`posts`/`all`/`replies`/…) is not reset when `targetId` changes, so navigating User(A)→User(B) keeps B on A's tab (e.g. Media on a profile with no media). Fix: `useEffect(() => setTab('posts'), [targetId])` (keep `featured` only if still valid — `hasFeatured` already guards the tab's visibility).
- **B6 (suggest keyboard nav dead). `Explore.tsx:778-783`** — `ExploreSuggestPopup` receives hardcoded `activeIndex={0}`; there is no keyboard up/down handling, so `active` highlight never moves and `pickSuggestion(index)` can never receive `index > 0` from the keyboard. Either wire arrow-key navigation in `ExploreSearchBar` or drop the `activeIndex` prop. Cosmetic.
- **B7 (unvalidated background URL). `ProfileHeader.tsx:287-297`** — `account.backgroundUrl` renders directly into `Image source` with no `safeHttpUrl` gate, unlike every avatar path (`PostCard.tsx:197`, `UserHoverCardView` uses `safeHttpUrl` for banner at `UserHoverCard.tsx:169` but **not** for avatar at `UserHoverCard.tsx:231` either). Upstream `backgroundUrlOf` (`packages/fedi/src/misskey/adapt.ts:150`) returns the raw string without scheme validation. Non-http(s) value → RN image fetch of an untrusted scheme. Fix: `safeHttpUrl` at the adapter (covers all consumers) or at the render site.
- **B8 (minor). `Note.tsx:501`** — root-replies `keyExtractor={item => item.id}` lacks the `${sessionId}:` prefix every other list uses (`HomeFeed.tsx:345`, `PostFeed.tsx:104`, `Followers.tsx:258`). Harmless today (single-session screen) but inconsistent; add the prefix.
- **B9 (minor). `PostPoll.tsx:67-70`** — `selected`/`voted` initialized once via `useState` initializer from `poll` props; a refetched `poll` (vote counts arrive, `voted` flags change) does not resync local state. Add a `useEffect` keyed on `poll.options` voted flags, or key the component by poll id+version.
- **B10 (minor). `Followers.tsx:88-167` / `Following.tsx`** (duplicated file, ~identical 304 lines) — `setError(null); setUnsupported(false); setDenied(false)` runs on **every** `load`, including `load('more')`, so a next-page failure clears a previous error caption mid-list. Cosmetic; also the two files are copy-paste duplicates — extract a shared `useFollowList(kind, id)` hook.
- **Non-bugs verified sound**: query keys are sessionId-first everywhere (`keys.ts:feedQueryKey`, `notificationsQueryKey`, `relationshipQueryKey`, thread/reply/repost/reaction keys); `createQueryKey` throws on empty sessionId. `useThreadRepliesQuery` is `enabled: parentId.length > 0 && backend != null`, so `NoteScreen`'s `rootParentId = ''` pre-focus does not fire (`usePostThread.ts:127`). `useNewPosts` (`HomeFeed.tsx:71-85`) setState-during-render is the documented render-phase-adjustment pattern, keyed per `feed.queryKey`. Translation breaker: manual translate never consults/records (`PostCard.tsx:435-444` vs auto path `PostCard.tsx:776-824`), 403×2 blocks only auto, non-403 resets — matches its spec. HoverPreview ghost/drift/revive: `pointerRecentlyMoved` gate (`HoverPreview.tsx:544`), stays-inside ghost filter (`583-587`), crossing-only revive (`596-606`), anchor-drift poll with settle grace (`336-353`), single-timer close (`535-538`) — coherent; residual nits: `leaveAt` stamps even when the card never opened (a later card-enter within the fade window can revive a never-shown card), and the `ResizeObserver → setFix(null)` loop (`395-396`) can jitter tall cards near viewport edges. `User.tsx` generation guards + state reset on `load` change correctly prevent cross-profile data flash. `Notifications.tsx:302-306` resets dismiss/clear-unsupported flags per session. Followers/Following reset + generation-guard on `(session, backend, id)`. No fake data found; signed-out states are honest everywhere. Explore tab state (`submitted` query text) intentionally persists across account switches while results refetch under the new backend — correct.

## Quality issues

- **Q1 — Inert-control compliance is good, but the user submenu is 7 dead rows.** `menuModel.ts:240-254`: RSS, user-search, memo, add-to-list, add-to-antenna, notify, refresh-remote all render `disabled` with `LATER('…')` reasons. The Capabilities rule permits disabled-with-reason, but seven permanent dead rows in every User submenu is clutter that trains users to ignore disabled states. Recommend hiding `LATER` rows behind a dev flag or collapsing them into one "More actions (not in this build)" disclosure until wired.
- **Q2 — Duplicated post-menu-adjacent logic.** `PostMenu.tsx:60-98` (`exec`/`execConfirm`/`execReport` triplicated try/catch-toast); `ActionBar.tsx:192-203` quote-disabled reasoning duplicates the `quote_posting` capability branch also encoded in `menuModel.ts`. `Followers.tsx`/`Following.tsx` are near-identical 304-line duplicates. `MediaGrid.tsx` (generic grid, 205 LOC) vs `PostMediaGrid.tsx` (438 LOC) — two media grids; check which screens still use the generic one and whether one can go.
- **Q3 — Performance: no list virtualization tuning anywhere.** Zero `React.memo` on `PostCard`/`ThreadRow`/`ReactionChips`/`PostQuote` (grep clean), no `getItemLayout`/`windowSize`/`maxToRenderPerBatch`/`removeClippedSubviews` on any of `FeedView`, `NoteScreen`, `Explore` lists, `Notifications`, `RecommendationsFeed` (grep clean). `FeedView` memoizes data transforms well; the gap is render-side. Additionally per-mount cost multipliers: `UnfurledLinkCard auto` fires `fetchLinkPreview` on mount for every bare-URL post when Data Saver is off (`PostCard.tsx:1179-1181`, `LinkCard.tsx:182-196`) — a link-heavy feed issues N parallel unfurls; consider `onEndReached`-adjacent or viewport-gated prefetch. Each media tile mounts its own `expo-video` player (`PostMediaGrid.tsx:229,253,281`) — a video-heavy feed holds many players; consider lazy player creation on visibility.
- **Q4 — Accessibility touch targets.** `ActionBar` compensates small art with `hitSlop` (`ActionBar.tsx:114, 282`) — good. But `PostMenu` rows (`PostMenu.tsx:22`: `paddingVertical: space.sm`) and poll options (`PostPoll.tsx:22`: `paddingVertical: 8`) may land under 44dp; `ExploreSuggestPopup` options (`atoms.py_sm/px_md`) similarly. Audit pass with a 44dp lint or explicit `minHeight: 44` (as `ReportChooser.tsx:236` already does) would close this.
- **Q5 — `RecommendationsFeed` capability inconsistency.** `RecommendationsFeed.tsx:126` passes `capabilities={backend?.capabilities ?? null}` from the **injected** backend prop only, while `FeedView` resolves the store backend when the prop is absent (`HomeFeed.tsx:156-157`). If `backend` is undefined here, reaction chips/menu gates see `null` capabilities (treated as unknown/signed-out-ish) instead of the session's real ones. Resolve via `useBackendForSessionId(sessionId)` like `FeedView`.
- **Q6 — ExploreSearchBar `busy` prop is never passed** (`ExploreSearchBar.tsx:19`, no `busy=` at `Explore.tsx:772`). Dead prop; remove or wire to suggest-fetch state.
- **Q7 — No TODO/FIXME debt in scope** (grep clean except `LATER()` menu rows and a `REASON_NEEDS_MASTODON` constant). 429 handling exists only in `User.tsx`; translation-breaker 429 references are spec comments.

## Top 5 fix priorities

1. **Thread `sessionId` into `ReactionChips` + `PostQuote` (B1).** Wrong-session emoji resolution in multi-account columns is the only cross-account correctness bug found. 4-line fix in `PostCard.tsx:1182,1131`.
2. **NewsTab load-more robustness (B2).** Silent load-more failure + stale-closure dupes is the only data-loss-shaped bug. Functional updater dedupe + footer retry in `Explore.tsx:600-629`.
3. **429 honesty in `NoteScreen` (B4) + `TagScreen` descriptor sanitization (B3).** Both are small, both mirror existing patterns (`User.tsx:140`, `Explore.tsx:59`). Do together.
4. **Validate `backgroundUrl` scheme (B7) + reset profile `tab` on `targetId` change (B5).** Untrusted-scheme image source is a (small) security-adjacent hole; sticky tab is user-visible wrongness. Both one-liners.
5. **Performance pass on feed lists (Q3).** `React.memo` on `PostCard`/`ThreadRow`, `windowSize`/`maxToRenderPerBatch`/`removeClippedSubviews` on `FeedView` + `NoteScreen` FlatLists, and viewport-gated link-unfurl. Measure with a 200-post timeline before/after; this is the only item needing profiling rather than review.
