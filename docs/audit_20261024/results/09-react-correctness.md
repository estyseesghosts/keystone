## Hook/exhaustive-deps findings

1. **Conditional hook — `useMemo` after early return (VIOLATION, highest severity).** `src/components/RichText.tsx:1031` returns early when `contentMode === 'plain'`, and `src/components/RichText.tsx:1045` (`const hasBlock = useMemo(...)`) runs only on the rich path. Toggling the device content mode changes the hook count between renders (3 hooks vs 4). React rules require all hooks before any return. Fix: hoist `hasBlock` above the `contentMode` branch (or compute both memos unconditionally). `useTheme` (`RichText.tsx:1002`), `useContentMode` (`RichText.tsx:1009`), `ctx` memo (`RichText.tsx:1010`) are correctly above the return — only `hasBlock` is misplaced.
2. **Set-state-during-render (tolerated pattern, extra render).** `src/screens/HomeFeed.tsx:75-78` (`useNewPosts`) calls `setBaseline` in the render body on first load / feed-key change. This is the React-endorsed derived-state pattern but costs a second render per feed switch; converting to `key={feedKey}` remount or lazy-init + effect would remove it.
3. **Ref mutation during render.** `src/state/streaming.ts:482` (`watchIdsRef.current = watchIds ?? []`) writes a ref in the render body of `useFeedLive`. Works (ref, not state) but is a side effect in render; move into the capture-sync effect at `streaming.ts:569`.
4. **Effect without dep array (intentional, lint-flagged).** `src/screens/Note.tsx:460-462` syncs `refreshThreadRef.current = refreshThread` on every render by design (comment at `Note.tsx:456-458` explains why deps must stay empty). Correct, but any future state read added to that effect becomes a stale-closure trap; keep the comment.
5. **`useMemo` dep uses optional-chain member.** `src/components/Post/PostCard.tsx:853-859` deps `[shownTranslation?.text, originalTags]`: if the translation object identity changes with identical text the memo correctly holds, but if text is later nested deeper the dep silently misses. Prefer extracting `const shownText = shownTranslation?.text` and depending on that variable. Same shape at `PostCard.tsx:766-773` (`srcSupported/srcLang/srcFetch` scalars — those are fine).
6. **`useSuggestions` effect deps are a lossy projection.** `src/components/Composer/Autocomplete.tsx:64` deps `[tkey, backend]` while the effect body reads `trigger.kind`/`trigger.query`. `tkey` (`Autocomplete.tsx:36`) encodes both, so behavior is correct today, but exhaustive-deps flags `trigger`; a future field read (e.g. position) would go stale silently. Depend on `trigger` (memoized at `Autocomplete.tsx:34`) or document the projection.
7. **Missing memoization where needed (not violations, but load-bearing absences):**
   - `src/state/cache/postActions.ts:354-396` (`usePostActions`) returns a brand-new `PostActions` object with fresh `toggle` closures and `set` callbacks **every render**, unmemoized. Every `PostCard` in every feed allocates this per row per render and hands it to `ActionBar` — memoization downstream is impossible.
   - `src/components/Post/PostCard.tsx:402-488` builds the post menu via `buildPostMenu({...})` inline during render (not in `useMemo`) on every render, including a fresh `recommendation` closure object (`PostCard.tsx:378-398`).
   - `src/components/Post/PostCard.tsx:874-896` (`handleLinkPress/handleMentionPress/handleHashtagPress/openPost/openQuoted`) are fresh closures every render and flow into the `RichText` `ctx` memo (`RichText.tsx:1010-1029`), invalidating it every render — so `RichText`'s one `useMemo` never memoizes in the `PostCard` path.
8. **Confirmed GOOD (no action):** `LivePostCard` keeps all hooks above the `isDeleted` early return (`PostCard.tsx:372-400`, comment states the rule); `HoverPreview` web-guard return (`HoverPreview.tsx:515`) sits after all hooks (`HoverPreview.tsx:486-505`); `UserHoverCard` platform branch (`UserHoverCard.tsx:53`) is in a hook-free splitter with hooks isolated in `UserHoverCardLoader`; `RecipientSection` hooks precede its `direct`-only return (`ComposerSections.tsx:401-405`); `MentionChip`'s `useContext` (`RichText.tsx:477`) precedes the static-chip return with the resolving hook isolated in `ResolvingMentionChip`; composer autosave effect (`Composer.tsx:229-253`) has correct deps + cleanup; `User.tsx:77-112` uses a generation counter against async races; Explore/Users/Tags/News/InClips effects all use `cancelled` flags with cleanup (`Explore.tsx:241-256, 292-317, 399-438, 552-574`; `Note.tsx:226-241`); `useFeedLive` subscription effect (`streaming.ts:484-562`) reads `backend.stream()` inside the effect with full cleanup; chat live effects (`chat.ts:316-349`) return the disposer.

## Re-render/memo findings

1. **Zero `memo()` wrappers in all of `src`.** Grep for `memo(` (excluding `useMemo`) returns no component wrappers. `PostCard`, `ThreadRow`, `RichText` (+`Inline`/`Flow`/`Fn`), `ActionBar`, `ReactionChips`, `PostPoll`, `PostQuote`, `ThreadRow`, `FeedView` rows — none memoized. Combined with finding 7 above, every feed scroll/pill/stream event re-renders every row's full subtree.
2. **Large unmemoized monoliths.** `PostCard.tsx` (1215 LOC, ~15 `useMemo`s but no split), `RichText.tsx` (1062), `Navigation.tsx` (1413). `Sidebar` (`Navigation.tsx:756-1002`) recomputes `backend` via `useMemo` (`Navigation.tsx:760`) but re-renders on every `leaf` change along with all rows; `MainTabs` (`Navigation.tsx:1019-1063`) remounts tab screens when `session` flips (conditional `session ? ... : ...` navigator children) — correct for auth scoping, but it also drops tab state on any session-object identity change (not just sign in/out).
3. **`StyleSheet.create` inside render (new style identity every render):**
   - `src/components/Profile/UserHoverCard.tsx:179` (`UserHoverCardView` — runs per hovercard render).
   - `src/components/Composer/Autocomplete.tsx:90` (`SuggestionList`) and `src/components/Composer/Chip.tsx:26`.
   - `src/components/Composer/Composer.tsx:493` — inside `useComposerController`, so a fresh stylesheet object is built on **every keystroke** and fanned out as `c.styles` to all sections. Hoist to module scope (theme-dependent values can stay inline).
   - Module-level (fine): `PostCard.tsx:82`, `PostMediaGrid.tsx:64`, `ActionBar.tsx:36`, `LinkCard.tsx:33`, `CompactComposer.tsx:500`, `ComposerSections.tsx:95`.
4. **FlatList `renderItem` inline closures.** `HomeFeed.tsx:368-381`, `PostFeed.tsx:105-117`, `Explore.tsx:281, 374-380, 499` all allocate a new `renderItem` arrow per parent render; combined with unmemoized `ThreadRow`/`AccountRow`/`TagChip`, virtualization cannot skip rows. `keyExtractor` is stable and correct (`HomeFeed.tsx:345`, `PostFeed.tsx:104` use `` `${sessionId}:${item.id}` ``).
5. **Context/provider granularity — mostly good, one coarse selector:**
   - `SessionProvider` value memoized (`SessionProvider.tsx:25-30`); `QueryProvider` client/persister stable via `useState` (`queries/Provider.tsx:72-73`). Good.
   - Coarse: `useActiveBackend` (`HomeFeed.tsx:49-55`) and `useBackendForSessionId` (`HomeFeed.tsx:58-66`) subscribe to the **whole session snapshot**; any session-store emit (token hydrate, scope-health mark, unrelated account change) re-renders every consumer, and `backendForSession(session)` allocates a new `Backend` per snapshot even when the session is unchanged. Select per-session outside the snapshot or memoize backend per session id.
   - `useScopeHealth` (`SessionProvider.tsx:98-106`) passes an inline `getSnapshot` selector that calls `store.scopeHealthSnapshot(sessionId)`; if that returns a fresh object per call, `useSyncExternalStore` will loop or re-render constantly. Verify `scopeHealthSnapshot` returns a stable reference (cached, not `{...}` per call).
   - `PostCardHandlersContext` default `{}` (`handlers.tsx:39`) allocates once at module scope (fine); `usePostCardHandlers` (`handlers.tsx:42-45`) spreads into a new object per call — trivial, but it feeds the `translationSource` memo dep `handlers.targetLang` (`PostCard.tsx:361`), so any context change refires translation setup.

## State/race findings

1. **Composer autogrow fix — verified SOUND.** `src/components/Composer/useAutogrowInput.ts:55-91`: growth via `onContentSizeChange`, shrink via imperative `remeasure` with synchronous DOM restore (`useAutogrowInput.ts:75-81`, the documented frozen-box guard), post-commit effect on `[text, remeasure]` covering drafts/restores/picks, clamping + identical-height bailout preventing loops. Both call sites wire all three hooks correctly (`Composer.tsx:558, 589-605`; `CompactComposer.tsx:151, 194-225`). Native path degrades to event-only growth (`asWebNode` returns null off-web) — correct, since RN measures content height natively.
2. **Composer double-submit race (real).** `useComposerController.submit` (`Composer.tsx:352-482`) never checks `busy` at entry; the guard is only the button's `disabled` prop (`Composer.tsx:569`; `CompactComposer.tsx:347`). A second submit dispatched before the first `setBusy(true)` commits (keyboard submit, double-tap, both composer chromes mounted) runs validation + upload + `create.mutateAsync` twice. Add `if (busy) return` (ref-mirror, since state lags) at the top of `submit`.
3. **`PostPoll` stale derived state.** `src/components/Post/PostPoll.tsx:66-68` initializes `selected`/`voted` from the `poll` prop once. If the poll object updates (vote echo via stream, refetch, optimistic patch), the checkboxes and `locked` (`PostPoll.tsx:69`) stay frozen on mount values. Either key the component by poll version or sync via effect on `poll.options`.
4. **`Explore.tsx:600-615` (`NewsTab.loadMore`) stale closure.** `seen` is built from `links` captured at call time while the update uses functional `setLinks`; two overlapping `loadMore` calls dedupe against the same stale snapshot. The `loading` guard makes overlap unlikely but not impossible (guard is state, also lagging). Snapshot `links` into a ref or compute dedupe inside the functional update.
5. **Follow/unfollow double-tap — OK in audited paths.** `UserHoverCardLoader.toggle` (`UserHoverCard.tsx:89-106`) guards with `busy`; post-level toggles serialize through the per-(session,post,kind) `ToggleQueue` (`postActions.ts:77-111`). `ProfileActions` follow path (`src/components/ProfileActions/ProfileActions.tsx`) holds only `error/listsOpen/lists/loadError/started` state — no `busy`/`isPending` guard was found on its follow control; confirm the mutation button disables while pending or rapid taps will fire concurrent follow/unfollow (the queue is post-scoped, not graph-scoped).
6. **Account/feed switch races — mostly guarded.** All query keys carry `sessionId` first (spot-checked `accounts.ts:19,48`, `adminInsight.ts:57-58`, `adminReports.ts:60-67`, `chat.ts:122-207`, `usePostFeedQuery.ts:217-218`); streaming mounts dispose on `[sessionId, descriptor, backend, ...]` change (`streaming.ts:562`); scroll restoration is keyed per session+descriptor (`HomeFeed.tsx:186, 250-263`); `User.tsx` generation counter + `Explore` cancelled flags (cited above). Two gaps:
   - `Note.tsx:440` calls `useThreadRepliesQuery(sessionId, rootParentId, ...)` with `rootParentId = ''` before the thread resolves — verify the hook disables on empty id, otherwise every Note mount fires one junk fetch.
   - `Note.tsx:501` `keyExtractor={item => item.id}` omits the `sessionId` prefix every other feed list uses (`HomeFeed.tsx:345`); after a rapid account switch, recycled rows keyed by bare id can flash the previous account's content before data swaps.

## Top 5 fix priorities

1. **Fix the conditional `useMemo` in `RichText`** (`RichText.tsx:1031-1045`). A rules-of-hooks violation in the single chokepoint renderer every post body passes through. Hoist `hasBlock` above the `contentMode` early return. Small, safe, test-covered.
2. **Stop the feed-wide re-render cascade.** Memoize `usePostActions`' return (`postActions.ts:354-396`), wrap `buildPostMenu` in `useMemo` (`PostCard.tsx:402-488`), stabilize PostCard's link handlers with `useCallback`, and add `memo()` to `ThreadRow`, `PostCardView`, and RichText's `Inline`/`Flow`. This is the highest aggregate perf win; measure with a feed-scroll render count before/after.
3. **Close the async races: composer double-submit + `PostPoll` stale vote state.** Guard `submit` with a busy ref (`Composer.tsx:352`) and sync or key `PostPoll` selection on the `poll` prop (`PostPoll.tsx:66-69`). Both are user-visible double-post / stuck-vote bugs.
4. **Tune `FlatList`s and unify keys.** Add `getItemLayout` (fixed-estimate ok), `windowSize`, `initialNumToRender` to `FeedView`/`PostFeed`/Explore lists; prefix `Note.tsx:501` keyExtractor with `sessionId`; verify `useThreadRepliesQuery` disables on empty id (`Note.tsx:440`).
5. **Bring small targets to 44pt and unify link-failure feedback.** Audit follow button (`UserHoverCard.tsx:245-256`), Discussions pill (`Explore.tsx:180-190`), and Caption-tap targets (`PostCard.tsx:910-917, 1024-1038, 1082-1105`) against the touch-target test; make `PostCard`/`RichText` link failures toast like `LinkCard` does (or document why silent).
