# Keystone v2 audit — synthesis (2026-10-25)

Twelve agents audited the repo in parallel. Each wrote a report in `results/`. This document merges them, removes duplicates and ranks the findings.

**Method and limits.** Every audit was static code reading. No agent ran the app on a device, a simulator or a live server. The one exception is the build agent, which ran the gates. The richtext agent also measured a few parser timings with a throwaway test. Findings marked "needs device check" are inferred. The Misskey agent recalled parts of upstream behavior from memory because no Misskey or Sharkey source is in the repo (M5, M6, M7 in its report). `pnpm audit` was not run. The RN UI agent did not review Settings, ProfileEditor, Login, Drive, EmojiPicker, richtext or the alf token files. The a11y agent found no `src/features`, so deck, columns and widgets were not audited.

**Gates.** `pnpm typecheck` (ios, android, web), `pnpm lint` and `pnpm test` all pass: 218 suites, 2968 tests, no snapshots, no skips. Tests are plentiful, but Misskey and Sharkey fixtures are synthesised, so they cannot catch wire-shape errors. Jest's `crypto` mock is `{}`, which hides the native `crypto` bug below.

## Overall assessment

The architecture is sound where it matters most: tokens are bound to a session and origin at the transport layer, cross-origin requests are refused before any I/O, content parses to an allow-listed AST, and no `innerHTML`, `eval` or WebView exists. Query keys carry `sessionId`. Custom lint rules hold the package boundaries.

The weak spots sit at the edges:

1. **Data lifecycle.** Secrets are stored in plaintext, and nothing is cleaned up on sign-out.
2. **Native runtime assumptions** that the tests mock away.
3. **Wire-shape correctness** on both backends, where the fixtures cannot catch mistakes.
4. **Missing resilience.** There is no cancellation, no offline awareness, no backoff and no error boundary.
5. **Media and lightbox** behavior.

## Findings by theme

### Security
- The Misskey token travels in the POST body, and `fetch` follows redirects by default. A 307 or 308 from a hostile instance could replay it to another origin (`misskey/client.ts:200`, `core/http.ts`). Per-request origin binding exists, but redirects bypass it.
- `ChatThread.tsx:51` passes an unvetted server URL to `Linking.openURL`. `openExternal` also allows `mailto:`.
- The MiAuth callback uses the `keystone://` custom scheme with no binding secret. The debug-signed build (#6) makes this worse.
- `http://` instance origins are accepted for any host.
- The Mastodon streaming origin is advertised by the server and receives the bearer token. The networking agent says it is never wired in, so this may be dormant today.
- The Misskey WebSocket URL carries `?i=<token>`.
- Any `<img class="emoji">` in post HTML loads an arbitrary URL (IP leak, plaintext http). `a.mention` can disguise any URL as a profile chip, and link label and target are never compared (richtext F6, F7).

### Privacy
- New posts always start as Public. `defaultVisibilityFor` is never given the account's default visibility.
- Link previews auto-fetch arbitrary URLs from the user's IP, with no private-IP guard and an unbounded body read. Every rendered federated post also fires a direct fetch to its remote origin.
- Drafts persist in cleartext, never expire and survive logout. Uploads keep EXIF. There is no app-switcher protection. Some permissions go unused.
- Auto-translation sends private note text to the server's translator.
- Session and account scoping of cache keys looked solid.

### Networking
- Request bodies are read outside the timeout and the caller's abort. Nothing passes a `signal`, so nothing is cancellable.
- There is no `onlineManager`, `focusManager` or AppState wiring.
- Both WebSocket fast-close breakers are reset by their own `open` handlers, so an accept-then-close server loops forever.
- `backend.stream()` is not pooled. The memoized backend resets on any session-store change. Streaming has no gap fill, and each update triggers an uncoalesced fetch.
- Mastodon media upload inherits the 30-second timeout.
- The Idempotency-Key is minted per call, so retries can duplicate posts (networking L2, mastodon 8).
- Mastodon client still has `err instanceof DOMException` (`mastodon/client.ts:155` or `:354`), which `core/http.ts` already fixed for Hermes.
- Boot blocks on untimed network calls. A post-boot 401 is never handled.

### Data storage and sessions
- A corrupt or version-mismatched session envelope is overwritten with an empty one, which signs out every account (storage S4).
- `hydrate()` can resurrect a removed session. A stale vault token can override a newer one. `signOutEverywhere` can wipe a session added mid-flight (S5, S6).
- The persisted-cache buster is independent of storage and session schema. Downgrades discard prefs and drafts. Orphaned MiAuth pending rows remain.
- `settleInto` (`src/state/cache/postActions.ts:116`) applies the whole post shadow, so a later failed toggle cannot roll back in the UI.
- `mergeChatMessage` drops every page except the first.
- There is no fallback after removing the active account. `setListMember` is not serialized. Optimistic writes do not cancel in-flight fetches.

### Mastodon
- Search never sends `resolve=true`, so remote handles and post URLs cannot be found.
- Capabilities are wrong: pinned posts are declared unavailable on vanilla Mastodon, and `polls_multi` is "unsupported".
- Hidden-total polls render fake zeros, which breaks the "never ship fake data" rule.
- Notification read state is never available. `lists.timeline` ignores a cursor continuation. Drafts cannot send `sensitive` or `language`.
- Low: unknown notification types render as raw strings, stream deletes are never applied, one malformed row fails the whole page, pagination parsing has no unit tests, and token revocation may use the wrong app after re-registration.

### Misskey
- `users/search` emits a pagination cursor the request never uses, so page 2 repeats page 1.
- Reaction emoji URLs are looked up by exact key, but the repo's own docs say the packed maps use bare keys. Real custom reactions then look unresolved.
- Stock Misskey is flagged `status_editing: supported`, which contradicts the repo's task doc. The `notes/edit` shape is unverified, and an edit cannot remove all attachments or clear a poll.
- Sign-out revoke sends no `token` or `tokenId`, so it is likely a no-op.
- Low: `isPureRenote` throws if `fileIds` is absent, rejected quote lookups stick forever, one stream handler exception aborts the others, and `movedTo` is never mapped.

### Media
- The lightbox has no zoom, pan or swipe-to-dismiss, breaks on rotation, has no web paging, and mounts every frame and player at once.
- Videos and audio never pause on scroll-off, unmount or backgrounding. gifv autoplays on every post.
- Feed, avatar, banner and emoji images use React Native `Image` rather than expo-image. There is no cache policy. `Media.blurhash` is adapted but never read, and sensitive media is hidden but not blurred.
- Aspect ratio is measured after load, so layout shifts.
- The 10 MB upload cap applies to video and ignores server limits (also richtext F9). Uploads have no cancel or byte progress, and removing an item mid-upload orphans the server file. Files are read fully into JS memory.

### React Native UI and composer
- No error boundary exists anywhere, so a render-time throw blanks the screen (rn-ui M1, a11y 10).
- ESLint has no `react-hooks` plugin, so hook-dependency bugs go unchecked.
- `Channels.tsx` has no cancellation on tab or account switch, so a stale response can land under the wrong tab. A failed `loadMore` discards the loaded list.
- `ToastHost` ignores the safe area and tab bar. Signed-out deep links to `/notifications` or `/users/:id` silently land on Home.
- The edit composer autosaves as a new-post draft, and "Save draft" creates a server draft of the edit. Attachments can be removed or alt-edited during an in-flight submit.
- Nested `$[x4 ...]` compounds font size without a cap. `contentFromHtml` throws `RangeError` on roughly 3000 to 5000 levels of nesting despite its "never throws" contract (measured).
- `numberOfLines` is ignored when a block node is present. Instance char limits are read once, and fallback defaults can wrongly block posting.

### Accessibility and i18n
- Time and number strings are English-only and ignore the app locale. Relative timestamps never refresh. Plurals are hand-rolled.
- Toasts are not announced, dialogs have no modal role, `Heading` has no header role, and the recommendation chips are unlabeled.
- `faint` text fails contrast (about 2.8:1 in light mode).
- Hover cards are mouse-only, and the composer's focus ring is removed. RTL is not handled.
- Timer and listener cleanup looked solid.

### Build, process and hygiene
- `state/STATE.md` is 188 lines against a roughly 60-line rule, with stale counts (217 suites and 2967 tests against the actual 218 and 2968). Its entries and matching logs are dated 2026-10-26, a day ahead. An older "P6 Wave 3.2" pointer sits mid-file, so the next step is ambiguous. AGENTS.md says STATE is the continuity mechanism, so this matters.
- `ios/` is untracked and not gitignored, while `android/` is tracked.
- `--forceExit` and `--bail` hide leaked handles. Jest warned of a worker that failed to exit.
- oxlint covers only `src/`. No lint rule enforces sessionId-in-query-keys or no-innerHTML, though AGENTS.md calls for both. `react-native-*` and `@expo/*` imports pass `no-ui-in-fedi`.
- Possibly unused deps: `expo-asset`, `expo-constants`, `react-compiler-runtime`. Check peers before removing. `@react-native/typescript-config` is `^0.81.5` against RN 0.86.3.
- Tests carry 12 `as any` and 210 `as unknown as`. Non-test code has no `as any` and no `ts-ignore`.
- `app.config.js` still has a `TODO(D3, owner)` for the app name and bundle id. `devEngines.packageManager` pnpm "12.14.0" looks unusual and should be verified.

## Suggested order of work

1. **Data lifecycle (one slice).** Fix the SecureStore key encoding so the vault works. Stop duplicating tokens in MMKV. Set `allowBackup` to false. Add a persister dehydrate filter (drop DMs, chat, notifications and followers-only content). Add a full per-session wipe on sign-out and remove: query cache, persisted cache, post-shadow `clearSession`, drafts, recents. Fix the `hydrate()` and `signOutEverywhere` races, and stop overwriting a corrupt envelope.
2. **Native runtime.** Add a `crypto` source (`expo-crypto` or equivalent). Make the idempotency key stable across retries. Remove every `Math.random` fallback. Stop mocking `crypto` as `{}` in jest.
3. **Networking resilience.** Plumb `signal` and put the body read inside the timeout. Add `onlineManager` and AppState wiring. Add error-page backoff that honors `Retry-After`, and make the WebSocket breakers survive `open`. Stop redirects from carrying tokens (`redirect: 'manual'` or a same-origin check).
4. **Lightbox.** Honor the initial index, then lazy-mount frames, add paging on web, rotation handling, zoom and dismiss, and pause lifecycle.
5. **Wire-shape correctness.** Fix Misskey list wrappers, the search cursor, reaction emoji keys and the Mastodon dismiss route. Fix Mastodon capabilities and `resolve=true`. Verify the Misskey items against a real server on the rig. Add captured (not synthesised) fixtures.
6. **Release hygiene.** Use a real Android signing key. Bind the MiAuth callback with a secret or move to a verified link. Vet URLs before `Linking.openURL`.
7. **UI robustness.** Add an error boundary. Enable `react-hooks` lint. Fix the edit-composer attachment bug and its autosave collision. Apply the account default visibility.
8. **Process.** Rewrite `STATE.md` under 60 lines and correct counts and dates. Decide the `ios/` policy. Add lint rules for sessionId query keys and no-innerHTML. Run `--detectOpenHandles` once.
9. **Longer tail.** Lingui coverage and `plural()`, locale-aware time, accessibility roles and contrast, expo-image migration, blurhash.
