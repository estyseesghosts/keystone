## Verified endpoint inventory (upstream Misskey `develop` + live probes)

Against `misskey-dev/misskey@develop`
(`packages/backend/src/server/api/endpoints/chat/...`,
`.../stream/channels/chat-{room,user}.ts`,
`core/entities/ChatEntityService.ts`, `core/GlobalEventService.ts`,
`misskey-js/src/streaming.types.ts`) and live unauthenticated probes
(`dvd.chat` Sharkey 2025.4.7, `misskey.io` 2025.4.1-io):

| Endpoint | Params | Notes |
|---|---|---|
| `chat/rooms/joining` | `limit/sinceId/untilId` (+dates) | room list (memberships, `populateRoom: true`); `read:chat` |
| `chat/history` | `limit` (1–100, default 10), `room: boolean` | overview; `room:false` → 1-on-1, `room:true` → rooms; adds `isRead`; NO cursor |
| `chat/rooms/show` | `roomId` | packed `ChatRoom`; `read:chat` |
| `chat/rooms/create` | `name` (req, ≤256), `description` (≤1024) | 1/day limit 10; `write:chat` |
| `chat/messages/room-timeline` | `roomId` (req) + `limit/sinceId/untilId` | lite-for-room; AUTO marks read; `read:chat` |
| `chat/messages/user-timeline` | `userId` (req) + `limit/sinceId/untilId` | lite-for-1on1 (no packed users); AUTO marks read; `read:chat` |
| `chat/messages/create-to-room` | `toRoomId` (req), `text?` (≤2000), `fileId?` (text or file required) | `write:chat`, 500/hour |
| `chat/messages/create-to-user` | `toUserId` (req), `text?`, `fileId?` (same rule; not to self) | `write:chat`, 500/hour |
| `chat/messages/show` | `messageId` | detailed pack; `read:chat` |
| `chat/messages/delete` | `messageId` | own messages only; `write:chat` |
| `chat/read-all` | `{}` | marks everything read; `write:chat` kind (read availability) |
| stream `chatRoom` | `{roomId}` | events `message` (lite) / `deleted` (id) / `react` / `unreact`; client→server `read` marks read; `read:chat` |
| stream `chatUser` | `{otherId}` | same events; `read:chat` |
| `main` stream | — | `newChatMessage` broadcast (not separately subscribed this slice) |

Presence probes: `dvd.chat` (Sharkey 2025.4.7) answers `CREDENTIAL_REQUIRED`
on `chat/rooms/joining` + `chat/history` (PRESENT); legacy `messaging/*`
404s there (REMOVED). `misskey.io` 2025.4.1-io 404s all `chat/*`
(absent on that release; upstream `develop` HAS them → version skew is
handled by the existing 404→unsupported path, per screen).

Permissions: every chat endpoint declares `kind: read:chat | write:chat`;
missing grant → HTTP 403 `PERMISSION_DENIED` (verified in upstream
`ApiCallService.ts`); `miauth/gen-token` stores any permission strings
(verified — no allowlist), so adding `read:chat`/`write:chat` to
`KEYSTONE_PERMISSIONS` is safe on old servers. Old tokens 403 → the
existing 0.8 `notePermissionDenied` → global re-auth prompt. No new
prompt mechanism.
