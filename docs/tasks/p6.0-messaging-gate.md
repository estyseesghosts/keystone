# P6.0 — Messaging is gated, not invisible

Plan ref: `docs/clickstone.md` §0.9 (Wave 0)
Status: done
Branch: `p6.0-messaging-gate`

## Goal

Make the absence of DMs/chat detectable and honest: a `direct_messages`
capability flag, the post-menu DM row and a discoverable Messages entry
rendered disabled with a client-gap reason instead of a generic string or
silent absence.

## Read first

- `AGENTS.md` §6 (every action gated on `Capabilities`; disabled with a
  reason; never inert controls)
- `docs/clickstone.md` §0.9

  §2.1 item 1 (no DM inbox), §3.1 (Misskey chat absent)

  on Akkoma — no invented directory timeline)

  `src/Navigation.tsx`, `docs/note-options.md`

## Steps

- [x] 1. `direct_messages` in `FeatureKey` / `FEATURE_KEYS`, `unsupported`
      on every detected flavor (misskey, sharkey, catodon, pinetree,
      mastodon, akkoma, pleroma), `unknown` for an undetected server.
- [x] 2. `chats` left untouched (Misskey chat server feature) — the gate
      does not overload it.
- [x] 3. Shared `messagingUnavailableReason()` in `src/lib/messaging.ts`
      (Lingui macro, client-gap sentence; fedi stays Lingui-free).
- [x] 4. Post-menu `dm` row built by `dmRow()`: gated on the flag, present
      and disabled with the reason; enabled only when the flag is
      `supported` AND a composer handler is connected.
- [x] 5. Account menu `Messages` row in `Navigation.tsx`, disabled with the
      same reason; no route, no stub screen.
- [x] 6. Tests: detect (both families), menu row, account-menu entry, reason
      semantics.
- [x] 7. Locale catalogs re-extracted/compiled; `docs/note-options.md` row
      updated.
