Plan ref: `docs/clickstone.md` §0.8 (Wave 0; full-audit `misskey-admin.md`

Status: done
Branch: `p6.0-misskey-scope-upgrade`

## Goal

A Misskey-family 403 `PERMISSION_DENIED` marks the session and surfaces the
SAME global re-auth/upgrade prompt Mastodon uses — instead of only the
per-screen local handlers — without inventing a scope list the server never
returned.

## Steps

- [x] 1. Remove the blanket Misskey short-circuit in `scopeHealth`:
      recorded 403 → `needsUpgrade: true`, `generation: 'stale-permissions'`,
      `reason: 'misskey-stale-permissions'`, `missingScopes: []`; no
      recorded 403 → the old `not-applicable` / `misskey-no-scopes` answer.
- [x] 2. Global seam: `packages/fedi/src/misskey/client.ts` invokes a
      registered `PermissionDeniedObserver` from its single error path
      (`translateError` + the Drive upload 403 branch); authenticated calls
      only; observer failures cannot alter the thrown `ApiError`.
- [x] 3. `SessionProvider` registers the observer and forwards to
      `store.notePermissionDenied(sessionId)`; the marker is in-memory,
      per session, idempotent, cleared by a fresh `add()` (sign-in again)
      and by removal.
- [x] 4. `scopeHealthSnapshot(id)` (subscription-stable variant) +
      `useScopeHealth()` hook for `useSyncExternalStore`.
- [x] 5. Shell prompt: `ScopeUpgradeBanner` rendered once in
      `Navigation`, reading the active session's health. Misskey copy says
      the token predates a permission Keystone now uses; Mastodon keeps its
      scope-diff copy. Action = existing Login screen, origin prefilled via
      a new optional `Login` route param (no new route). No session clear,
      no revoke.
- [x] 6. Tests: store matrix (marked / per-session / cleared on re-auth /
      old unconditional result fails), transport observer
      (403/upload/404/500/unauth/misbehaving observer), provider
      end-to-end 403 → `scopeHealth`, banner (absent before, present after,
      action navigates with origin, Mastodon reuse, reactive hook).
- [x] 7. Clips/Drive/Following/Followers/Lists/Antennas/ProfileEditor/
      MutesSection local handlers untouched and still work as secondary
      explanations.

## Out of scope

- Persisting the denial marker across app restarts (see the session log's
  decision: runtime evidence, re-recorded by the next refused call).
- Revoking, clearing or silently re-authorizing the session.
- Inventing/deriving a Misskey scope list; `missingScopes` stays empty.
- Locale catalogue extraction/compilation (coordinator runs it after the
  merge; the new strings render English until then).
- An ADR: the in-memory-vs-persisted choice is local and reversible; the
  load-bearing decision is recorded in the log for the coordinator.
