# P6.1 — Reports that a moderator can use

Plan ref: `docs/clickstone.md` §1.5 (Wave 1)
Status: done
Branch: `p6.1-reports`

## Goal

Turn the single required-comment report dialog into the chooser Mastodon's
moderators need: `status_ids`, `category`, `rule_ids`, `forward`, an optional
comment, and the `write:reports` scope — without pretending Misskey's
`users/report-abuse` can carry fields it does not have.

## Steps

- [x] 1. Core API: `ReportCategory`, `ReportOptions`, `ReportResult`
      (`unsupported[]` = fields the family could not express, with the
      honest reason), `InstanceRule`, `normalizeReportOptions`; `Backend.
      reportAccount(id, options)` plus optional `Backend.instanceRules()`.
      A bare string stays accepted as the comment-only shorthand.
- [x] 2. Mastodon: `buildReportBody` + `reportAccount` send only chosen
      fields (`account_id`, `comment`, `status_ids[]`, `category`,
      `rule_ids[]`, `forward`); `rule_ids` forces `category: "violation"`
      (server does the same); empty arrays/false defaults are omitted.
      `fetchInstanceRules` reads `GET /api/v1/instance/rules`; 404/405 maps
      to the honest unsupported state.
- [x] 3. Misskey: `users/report-abuse` stays `{userId, comment}` (comment
      trimmed, empty refused locally because the server requires minLength
      1); `statusIds`/`category`/`ruleIds`/`forward` come back as
      `unsupported` with the reason. No `instanceRules` member.
- [x] 4. Scope: `write:reports` moved from `SCOPES_LATER` to `SCOPES_NOW`;
      OAuth + `scopeHealth` tests updated. No session revoked.
- [x] 5. UI: `ReportChooser` replaces the comment-only confirm — category
      (default = last used, device-local), optional rule checkboxes when
      the server publishes rules, forward toggle for remote accounts,
      optional comment (required on Misskey). The reported post's id rides
      `status_ids` from `PostHandlers`. Rules 404/empty/error render a
      reason, never an error page.
- [x] 6. Tests: Mastodon body include/omit cases, rule-driven violation,
      rules parsing/404/shape, Misskey shape + unsupported fields, scope
      split, chooser UI interactions, last-category store, session key.

## Out of scope

- Admin/moderation queue (Wave 3) and notification-based report results.
- Reporting a *collection* (`collection_ids`, Mastodon 4.4+): no UI for
  collections exists in this build.
- A status-picker step (Mastodon's `statuses.jsx`): the reporter acts on
  one post, which is sent as `status_ids[]`.
- Per-report anonymity options, `forward_to_domains` multi-domain selection
  (single remote target only).
- Live rig/device proof (rig down, no device pass in this slice).
