# P6.1 — Per-note `noQuote` and attach-time sensitivity

Plan ref: `docs/clickstone.md` §1.2 (Wave 1)
Status: done
Branch: `p6.1-composer-controls`

## Goal

The composer can refuse quotes for one note (create and edit, Misskey
family), each attachment can be marked sensitive at upload time where the
server takes a per-file field, and sensitive media in a post reveals per
tile instead of hiding the whole grid.

## Steps

- [x] 1. Capabilities: add `no_quote` and `media_sensitivity` feature
      keys. Misskey/Sharkey supported; Mastodon/Akkoma/Pleroma
      unsupported (MastoAPI has no per-note `noQuote` and no per-media
      `sensitive`); Catodon/Pinetree stay unknown (nothing unlocks them).
- [x] 2. `composeGates` gains `noQuote` and `mediaSensitive`, each with a
      specific disabled reason (unsupported vs not-reported are distinct).
- [x] 3. `ComposeState.noQuote` + `buildPostDraft` emits `noQuote: true`
      only when the gate is on (create omits false; edit omits false so an
      edit cannot silently lift a refusal the composer cannot show).
- [x] 4. Full `Composer` and `CompactComposer` (create + edit) render the
      toggle. Misskey family: enabled + per-note vs account-wide help.
      Mastodon family: disabled with a visible reason.
- [x] 5. `UploadItem.sensitive` threaded through `useUploads` →
      `uploadOne` → `uploadAll` → `uploadMedia({isSensitive: true})`;
      alt/comment behavior unchanged. Per-row toggle in `UploadsSection`
      (both chromes), locked after upload, disabled with a visible reason
      where the family only has status-level `sensitive`.
- [x] 6. Local drafts persist/restore `noQuote` (schema default false).
- [x] 7. `PostMediaGrid`: per-tile reveal (`media-sensitive-show-<id>`);
      a lone sensitive attachment keeps its existing single-tile render.
- [x] 8. Tests: fedi wire/gating, composer create/edit, Mastodon
      never-sends, upload flag, disabled reasons, per-tile reveal.

## Acceptance

- [x] `pnpm typecheck && pnpm lint && pnpm test` green
      (three tsc projects clean; oxlint+eslint clean; 152 suites / 1939
      tests)
- [x] `noQuote` reaches the Misskey create (`notes/create`) and edit
      (`notes/edit`) bodies only when on; Mastodon create body never
      carries `noQuote`/`quote_approval_policy`
- [x] Per-file sensitive reaches `uploadMedia` as `isSensitive` only on
      the Misskey family; Mastodon upload call carries no such field and
      the row renders the reason
- [x] Tapping one sensitive tile reveals only that tile; other sensitive
      tiles stay hidden and keep their own reveal control
- [x] No new wire fields invented; disabled controls always say why
- [ ] device/web visual run — not verified (jest-only slice)

## Out of scope

- Mastodon 4.5 per-status `quote_approval_policy` (a per-post refusal does
  exist there; the wire/contract does not carry it yet — follow-up).
- Status-level Mastodon `sensitive` on create (the whole-post flag).
- Editing sensitivity after upload (`drive/files/update` / Mastodon media
  update) — composer alt text is still upload-time only.
- Locale catalog extraction/compilation (coordinator runs
  `intl:extract` / `intl:compile`; new English strings fall back to their
  source).
