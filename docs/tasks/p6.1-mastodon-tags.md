# P6.1 — Mastodon: domain blocks, tag follow/mute, featured tags

Plan ref: `docs/clickstone.md` §1.4 (Wave 1)
Status: done
Branch: `p6.1-mastodon-tags`

## Goal

Wire the Mastodon curation surfaces the audit found missing: PERSONAL
domain blocks (data + Settings → Mutes), hashtag follow/unfollow and
profile featured tags (data + Tag screen), and an honest disabled row for
the hashtag mute neither server endpoint exists for.

## Steps

- [x] 1. Wire types: `Tag` gains optional `id`/`following`/`featuring`
      (serializer sends the flags only to an authed caller); new
      `FeaturedTag` wire row.
- [x] 2. Core API: `TagsApi` (`show?`, `follow`, `unfollow`, `followed`,
      `featured?`, `feature?`, `unfeature?`, `deleteFeatured?`) and
      `DomainBlocksApi` (`list`, `block`, `unblock`) as optional `Backend`
      members; `normalizeDomainBlock` input hygiene helper.
- [x] 3. Mastodon endpoints: `mastodon/tags.ts` (`GET /api/v1/tags/:id`,
      `POST …/follow|unfollow|feature|unfeature`, `GET /followed_tags`,
      `GET/POST /featured_tags`, `DELETE /featured_tags/:id`) and
      `mastodon/domainBlocks.ts` (`GET/POST/DELETE /api/v1/domain_blocks`).
      Feature/unfeature fall back to the `/featured_tags` calls ONLY on
      404/405 (older Mastodon).
- [x] 4. Flavor gate: Akkoma/Pleroma leave `featured*` undefined (no such
      endpoints); follow/unfollow and domain blocks stay defined. A
      runtime 404 disables the UI row with the reason, never errors it.
- [x] 5. Settings → Mutes: personal domain blocks row (list, normalized
      add, unblock, 100-cap note); placeholder with the reason when the
      backend/endpoint is absent.
- [x] 6. Tag screen: Follow/Unfollow (re-reads server state), Feature on
      profile/Don't feature (vanilla Mastodon), disabled "Mute this
      hashtag" row documenting the server gap.
- [x] 7. Tests: data-layer wire shapes/fallbacks/404s
      (`packages/fedi/test/mastodon-tags.test.ts`,
      `mastodon-domain-blocks.test.ts`), Mutes domain-block UI,
      Tag action UI.
