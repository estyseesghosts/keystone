# P6.1 — Mastodon lists and polls: send the fields the UI already implies

Plan ref: `docs/clickstone.md` §1.6
Status: done
Branch: `p6.1-list-poll-fields`

## Goal

List create/update carry `replies_policy` and `exclusive`, and poll create
carries `hide_totals`, each only where the server stores the field — with
honest capability flags, composer/list controls, and tests.

## Steps

- [x] 1. Capabilities: `lists_replies_policy`, `lists_exclusive`,
      `polls_hide_totals`. Mastodon supported (all three);
      Akkoma/Pleroma `lists_exclusive` supported, policy + hide_totals
      unsupported (permitted params / `make_poll_data/1`); Misskey,
      Sharkey, Catodon unsupported; Pinetree hide_totals unsupported,
      list flags unknown; unknown flavor → unknown.
- [x] 2. Core types: `ListRepliesPolicy`, `ListFields`, `ListSummary`;
      `ListsApi.create(name, fields?)` / `update(id, {name} & fields)` /
      `list()` extras; `PollDraft.hideTotals`.
- [x] 3. Mastodon backend: `adaptListRow`, `listFieldsBody` (title always,
      each optional field only when chosen AND supported); list reads
      report the policy/exclusive it can parse.
- [x] 4. Misskey backend: accepts the create `fields` argument and
      deliberately drops it (Misskey's `users/lists/create` paramDef is
      `name` only) — same signature, honest no-op.
- [x] 5. Mastodon compose: `poll.hide_totals` only when the draft says
      `hideTotals === true`; Misskey create/edit bodies still omit it.
- [x] 6. Composer: `composeGates.pollHideTotals` (distinct unsupported vs
      not-reported reasons), `ComposePollState.hideTotals`,
      `buildPostDraft` drops it when the gate is off, "Hide totals" chip,
      local-draft persistence (`pollHideTotals`, default false).
- [x] 7. Lists screen: create and inline edit expose the three reply
      policies plus an exclusive toggle, seeded from the row the server
      reported; both render disabled with a reason where unsupported or
      not reported, and only supported fields are put in the call.
- [x] 8. Tests (data layer + UI) for include/omit, unsupported/unknown
      gating, and the toggle interactions.
- [x] 9. `npx --yes pnpm@12.14.0 typecheck && lint && test` green.

## Acceptance

- [x] list create/update body has `replies_policy`/`exclusive` only when
      chosen and supported; omitted otherwise (Akkoma drops the policy,
      unknown flavor drops both)
- [x] poll body has `hide_totals: true` only when true and supported;
      omitted for false/absent and for Akkoma/Misskey
- [x] capability unsupported/unknown → control disabled with a reason and
      the field is never sent
- [x] full `typecheck && lint && test` green (see session log)

## Out of scope

- Composer language selection (clickstone §1.6 defers it).
- Mastodon web-UI parity for the poll form beyond the API field (the web
  UI has no hide-totals control; the API does).
- Creating/editing Mastodon list members from the list editor, and any
  per-list notification/mute settings.
- Re-probing the rig for Akkoma/Pleroma `hide_totals` behavior; the
  read-only source shows it is documented but not stored.
