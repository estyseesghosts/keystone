# P6.0.2 — Search is not one page

Plan ref: `docs/clickstone.md` §0.2 (Wave 0 — correctness)
Status: done
Branch: `p6.0-search-paging`

## Goal

Mastodon v2 search stops truncating at page 1: `search.posts` and
`search.accounts` page through the existing Link-cursor helper, and
`searchV2` returns the server's Link-derived next/prev plans instead of a
fabricated `{cursor: null, end: true}`.

- `docs/clickstone.md` §0.2
- `docs/2026-10-22-full-audit-mastodon-misskey-v1-parity/full-audit.md`

## Steps

- [x] 1. Extend `pagination.ts` cursors with `offset` (v2 search / trends
      page-number paging) and expose `prevContinuation` beside
      `nextContinuation`; both share one Link→continuation builder.
- [x] 2. `searchV2` accepts a `continuation` (next/prev plan) plus explicit
      `offset`/`maxId`/`minId`/`limit`; replays a same-origin server URL
      verbatim, carries cross-origin cursor params onto the session origin,
      and returns `{continuation, prev}` parsed from the Link header.
- [x] 3. `Backend.search.posts` / `Backend.search.accounts` send
      `type=statuses` / `type=accounts` (upstream pins combined search to
      offset 0, so only typed search can page) and map the result with the
      standard §5 end rule: no next link or empty page ⇒ `end`.
- [x] 4. Tests: next/prev Link, cross-origin cursor carryover, account
      paging, no-Link end, empty page with a next link.
- [x] 5. Misskey regression: `search.posts` still pages with
      `untilId`/`sinceId` (code untouched).
- [x] 6. Verify: typecheck + lint + full test trio.

## Acceptance

- [x] New test fails on the old code (4 failures: posts, accounts,
      cross-origin, prev) and passes after the fix.
- [x] A `Link: <...>; rel="next"` page yields a non-null cursor and
      `end: false`; following the cursor issues the server's next URL; a
      page without `rel="next"` yields `end: true`.
- [x] Account search paging covered.
- [x] No existing Mastodon search test encoded the one-page rule (nothing
      to update); suggestions keep their single-request signatures.
- [x] Misskey search paging regression added, Misskey code untouched.
- [x] `npx --yes pnpm@12.14.0 typecheck && … lint && … test` green
      (146 suites / 1769 tests).

## Out of scope

- Misskey search code (already pages).
- Search UI changes: `FeedView`/`usePostFeedQuery` already request the
  next page from `Page.cursor`; no screen touched.
- Any offset fallback when the server sends no Link: contract §5 says no
  next link is the end. Real Mastodon's `/api/v2/search` emits no Link
  header (reference `app/controllers/api/v2/search_controller.rb`), so it
  stays one page until it does — the client never invents a cursor.
