# P6.1 — Edit history, delete-and-redraft, media description update

Plan ref: `docs/clickstone.md` §1.7 (Wave 1)
Status: done
Branch: `p6.1-history-redraft-media`

## Goal

Make an edited post auditable (Mastodon revision history behind the
Edited badge), make "start over" possible on both families (delete then
reopen the composer with the payload), and stop alt text from being
locked after upload (Mastodon `PUT /api/v1/media/:id`, Misskey
`drive/files/update` `comment`).

## Steps

- [x] 1. Data layer: `PostRevision` in `core/models.ts`;
      `Backend.editHistory?(id)` (Mastodon `GET /api/v1/statuses/:id/history`)
      and `Backend.updateMedia?(id, {description?, focus?})`;
      `Backend.deletePost(id, {keepMedia?})`.
- [x] 2. Mastodon: `StatusEdit` wire type, `adaptStatusHistory` (server is
      OLDEST-first with the creation snapshot at index 0 → reversed to
      NEWEST-first, `original` kept on the server's first entry),
      `fetchStatusHistory`, `updateMediaAttachment` (description/focus only
      when set), `DELETE …?delete_media=false` for redrafts.
- [x] 3. Misskey: `updateMedia` → `drive/files/update` `comment`
      (no focus field exists — dropped, never sent); `editHistory` is
      ABSENT (no endpoint upstream); `Note.updatedAt` → `editedAt` so
      Sharkey edits badge honestly (absence = no badge).
- [x] 4. History screen `NoteHistoryScreen` at `/notes/:id/history`, opened
      from the Edited badge; revisions render through `RichText` over the
      allow-listed AST (`revisionNodes`); the badge is non-interactive
      where `editHistory` is absent; a 404 from a fork maps to the same
      honest "no history" state.
- [x] 5. Delete-and-redraft: menu row with confirm + `REDRAFT_WARNING`;
      `deleteAndRedraft` deletes FIRST (`keepMedia: true`) and only then
      seeds the composer (in-memory handoff, consumed once); failure means
      no composer. Composer seeds text/CW/visibility/localOnly/media(+alt)/
      reply/quote; polls are dropped deliberately.
- [x] 6. Media descriptions: composer seeds existing attachments (edit mode
      and redraft) with editable alt text; changed descriptions are saved
      through `updateMedia` BEFORE the post is written; uploads stay
      editable after upload where the endpoint exists, otherwise the field
      is disabled with the gate's reason.
- [x] 7. Tests (37 new) across the data layer, the redraft flow, the
      history screen, the composer media path, badge/menu gating and the
      route table.

## Acceptance

- [x] `pnpm typecheck && pnpm lint && pnpm test` green

- [x] History order documented and pinned: newest-first, `original` on the

- [x] A failed delete never opens the composer and never seeds
- [x] Redraft preserves media (Mastodon `delete_media=false`; Misskey keeps

- [x] Alt text edits reach the server on both families
- [ ] device/web visual run — not verified (jest-only slice; no live
      Mastodon with an edited post on the rig)

## Out of scope

- Rendering a revision DIFF (Mastodon's own UI shows one revision at a
  time; this screen lists revisions, not a character diff).
- Restoring/redrafting FROM a past revision.
- Focus (crop) editing in the UI: the Backend accepts `focus`, but only
  Mastodon supports it and no crop surface exists yet.
- Drive-screen caption editing (the Drive library already has its own
  file editor).
- Misskey edit-history: no server endpoint exists to call.
