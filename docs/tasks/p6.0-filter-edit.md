# P6.0.3 — Filter edit must not destroy keywords

Plan ref: `docs/clickstone.md` §0.3 (Wave 0 — correctness)
Status: done
Branch: `p6.0-filter-edit`

## Goal

A Mastodon v2 filter is a GROUP of keywords; reading only the first hid
the rest and editing wrote the siblings back as bare `{id}` rows. `list()`
now exposes every keyword, `update()` rewrites the primary in place and
PUTs every sibling with its own text and `whole_word`, and the Settings
row shows/edits the whole group without collapsing it.

## Steps

- [x] 1. `Filter.keywords: FilterKeyword[]` (`{id, keyword, wholeWord}`,
      server order, never empty) added to the domain model; `phrase`
      stays the first keyword for existing callers.
- [x] 2. `adaptV2FilterRow` maps every keyword (not just `keywords[0]`);
      `adaptV1FilterRow` maps its single keyword as `[phrase]` with the
      row id.
- [x] 3. `update()` v2 path continues to read-then-PUT but writes every
      prior keyword back: `{id, keyword: phrase, whole_word}` for the
      primary, `{id, keyword, whole_word}` unchanged for the siblings.
      No duplicate appended, no reorder, no bare `{id}` rows.
- [x] 4. Group `title`: a custom title is preserved; an auto-derived one
      (equal to the old primary keyword, or absent) follows the phrase.
- [x] 5. `FiltersSection` renders every keyword (`", "` joined) and the
      edit field edits the primary only, with the siblings named beside
      it. v1 stays one phrase.
- [x] 6. `serverFilterWordsOf` (feed enforcement) uses every keyword of a
      hide-action group, so the siblings are actually enforced.
- [x] 7. Tests: two-keyword list/update (ids + `keyword` + `whole_word`),

      v1 single-keyword path, UI multi-keyword row + primary edit.

## Out of scope

- Adding/removing keywords from the UI (the field edits the primary; the
  API still exposes create/update/delete a phrase). The data path keeps
  every sibling.
- `expires_in`/`filter_action` semantics (untouched beyond the existing
  round-trip).
- Locale catalogs: the one new UI string falls back to English source
  until the next `intl:extract` (slice forbids catalog edits).
- Live-server verification (rig down; unit tests + fixture only).
