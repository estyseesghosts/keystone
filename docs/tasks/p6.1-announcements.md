# P6.1 — Announcements read

Plan ref: `docs/clickstone.md` §1.12 (Wave 1)
Status: done
Branch: `p6.1-announcements`

## Goal

Implement the declared-but-dead `AnnouncementsApi` for both families — a
read path (Misskey `announcements`, Mastodon `GET /api/v1/announcements`)
plus a per-row dismiss where the server allows it — and one screen at
`/announcements` that lists notices newest-first with read state, honest
unsupported/empty/error states, and a dismiss action that is never inert.

## Steps

- [x] 1. Core: `Announcement` reshaped to what the UI can render honestly
      (`title: string | null`, `content: Content` = MFM/HTML source,
      `createdAt`/`updatedAt`, `imageUrl`, `icon`, `needConfirmationToRead`,
      `startsAt`/`endsAt`/`allDay`, `isRead: boolean | null`);
      `AnnouncementsApi.list` + optional `dismiss?(id)`.
- [x] 2. Capability `announcements` in `detect.ts`: supported on
      misskey/sharkey/catodon/mastodon/akkoma/pleroma, verified-absent on
      pinetree, `unknown` on an undetected flavor.
- [x] 3. Misskey family (`misskey/announcements.ts`): `announcements`
      (public, `limit`/`sinceId`/`untilId`) and `i/read-announcement
      {announcementId}` behind `dismiss`; adapts MFM text, severity,
      image, `needConfirmationToRead`, tri-state `isRead`.
- [x] 4. Mastodon family (`mastodon/endpoints.ts` +
      `mastodon/adapt.ts`): `GET /api/v1/announcements` (whole published
      list, no cursor) and `POST /api/v1/announcements/:id/dismiss`
      (encoded id); HTML content through `htmlContentOf`, no invented
      title/severity, `read` tri-state, `starts_at`/`ends_at`/`all_day`.
- [x] 5. 404/405 stays the honest absent signal: the list renders the
      "not available on this server" state; a dismiss 404 disables the
      button with the reason — never an error page, never a fake success.
- [x] 6. UI: `src/screens/Announcements.tsx` (route `/announcements`,
      route title, linking leaf), newest-first sort (Mastodon sends
      oldest-first), read indicator, dismiss with disabled reason when
      unsupported, pull-to-refresh, empty/error/unsupported states,
      signed-out sign-in prompt.
- [x] 7. Discoverable entry point: sidebar + account menu `Announcements`
      row gated on capability + module (hidden signed out).
- [x] 8. Tests: both endpoint shapes + adaptations, dismiss updates state,
      404 → unsupported (list and dismiss), route/nav drift, screen
      list/empty/error/dismiss/read-state cases.
