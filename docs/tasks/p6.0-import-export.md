## Goal

Make the Misskey transfer module speak upstream shapes: import uploads the
picked file to Drive and calls `i/import-*` with `{fileId}`; export reports
an enqueued job (rate limit + `exportCompleted` notification) instead of
awaiting a payload.

## Steps

- [x] Import executes `transport.upload(file)` (multipart
      `drive/files/create` through the existing client seam) and then
      `i/import-<kind>` with `{fileId}` only. No `{file: text}` anywhere.
- [x] Map `mute` to upstream `i/import-muting` (there is no
      `i/import-mute`); keep `notes` for forks, 404 surfaces honestly.
- [x] Keep the 10 MB guard before any network I/O; let the server own the
      file-type verdict (`UNEXPECTED_FILE_TYPE`/`TOO_BIG_FILE` ApiError).
- [x] Expose phases (`uploading` → `submitting` → `done`) and a result
      (`ok`, `endpoint`, `fileId`, English fallback message) for the future
      settings screen.
- [x] Export returns `status: "queued"` with the endpoint, the upstream
      rate window (notes 1/day), `delivery: "notification"`,
      `notificationType: "exportCompleted"`, and a message naming the
      limit. A fork returning a body yields `status: "payload"` instead.
- [x] `serializeExport` retained but documented as payload-only.
- [x] Tests cover following + notes (+ blocking/mute), multipart name/bytes,
      the no-`{file}` assertion, the size guard, no import call after a
      failed upload, all eight export endpoints, notes queued semantics,
      payload forks, and a 429 propagating.
- [x] UI stays a stub (`TransferSections.tsx` untouched); no Backend
      surface added (Wave 2 owns picker + wiring).
