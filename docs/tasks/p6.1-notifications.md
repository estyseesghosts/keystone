# P6.1 — Notification types and Mastodon dismiss

Plan ref: `docs/clickstone.md` §1.11 (Wave 1)
Status: done
Branch: `p6.1-notifications`

## Goal

Map the Misskey notification wire types that fell into `unknown` (with
honest labels, no invented actions), give them a filter home, and add
Mastodon per-row dismiss + clear-all behind endpoint support — with 404/405
surfacing as a hidden action with a reason, never an error wall.

## Steps

- [x] 1. Core `NotificationKind` gained `note`, `scheduledNotePosted`,
      `scheduledNotePostFailed`, `exportCompleted`, `roleAssigned`, `login`,
      `createToken`, `test`; `NotificationExt` gained `roleName`,
      `exportedEntity`, `exportedFileId`, `achievement`, `failedDraftId`.
- [x] 2. Misskey adapter maps the full `notificationTypes` vocabulary
      (including `achievementEarned` — the old table matched a bare
      `achievement` Misskey never sends — and the grouped
      `reaction:grouped`/`renote:grouped` labels), packs the per-type ext
      detail, and keeps `chatRoomInvitationReceived` as `unknown`.
- [x] 3. Misskey backend translates core preset KINDS to Misskey WIRE
      types (`achievement` → `achievementEarned`; unknown tokens pass
      through) and omits empty include/exclude params.
- [x] 4. Filter presets: new `notes` and `system` presets, gated to the
      Misskey family; `notificationFilterPresets(family)` hides what a
      family cannot serve. Screen falls back to `all` if the selected
      preset disappears (account switch).
- [x] 5. Mastodon: `POST /api/v1/notifications/:id/dismiss` (encoded id,
      no body) and `POST /api/v1/notifications/clear`; optional
      `Backend.dismissNotification?`/`clearNotifications?`. A preset whose
      kinds have no wire types now answers an EMPTY page instead of
      dropping the filter (which would return every row).
- [x] 6. Row UI: labels for every new kind, `chatRoomInvitationReceived`
      reads "chat invitation", viewer-event rows render no invented actor,
      packed role name / export entity render as a secondary line, and an
      optional per-row dismiss control renders only when a handler exists.
- [x] 7. Screen UI: per-row dismiss + `Clear all` with a confirm dialog,
      both only on the Mastodon family; 404/405 hides the action with a
      caption; other errors surface as a message beside the list.
- [x] 8. Tests: 15 fedi mapping/ext/preset-translation, 1 Misskey backend
      param-shape, 4 Mastodon dismiss/clear/404/empty-page, 8 row
      label/viewer-event/dismiss, 2 preset-family, 5 screen actions.
