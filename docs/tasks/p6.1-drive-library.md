# P6.1 — Drive as a library (upload, folders, file detail)

Plan ref: `docs/clickstone.md` §1.10 (Wave 1, after 0.7)
Status: done
Branch: `p6.1-drive-library`

## Goal

Drive is usable as a library: upload from the Drive screen into the
selected folder, browse files per folder (root included), and inspect a
file (`drive/files/show`) with the notes that attach it
(`drive/files/attached-notes`) — honest empty/unsupported states, no fake
counts.

## Steps

- [x] 1. `DriveApi.files` takes `folderId` (omitted/null = root, never put
      on the wire for root).
- [x] 2. `DriveApi.showFile(id)` → `drive/files/show {fileId}` adapted to
      `Media`.
- [x] 3. `DriveApi.attachedNotes(id, opts)` →
      `drive/files/attached-notes {fileId, limit, untilId}` paged as
      `Page<Post>` with the standard note pager.
- [x] 4. Drive screen: folder scope selector (Root + every folder) scopes
      the file listing; the list/load-more carry the folder; a deleted
      selected folder falls back to root.
- [x] 5. Drive screen upload: the composer's `pickMedia` picker stages one
      file, an optional description becomes `comment`, upload targets the
      selected folder (`folderId` only when a real folder), shows
      "Uploading…", keeps the stage and shows the server error on failure,
      and refreshes the list on success.
- [x] 6. File detail dialog: name/type/size/created/sensitive/comment/URL
      from `showFile` (falling back to the row values if `show` 404s),
      then the attached notes with paging.
- [x] 7. Honest gates: whole screen unavailable without `backend.drive`
      (Pinetree/Mastodon); folder section only with `drive.folders`;
      `show`/`attached-notes` 404 keep the section visible with a reason;
      empty folders and empty note lists say so; no note counts.
- [x] 8. Tests: fedi call shapes/adaptation/paging + screen upload,
      folder scope, detail, empty and 404 states.
- [x] 9. Verify: typecheck + lint + full test trio.

## Acceptance

- [x] New tests fail on the pre-slice code (10 failures: missing
      `folderId` param, missing `showFile`/`attachedNotes`, no upload UI,
      no detail dialog) and pass after.
- [x] `files({folderId: "d1"})` sends `folderId`; `files({folderId: null})`
      and `files()` omit it.
- [x] Upload into a selected folder calls
      `uploadMedia(file, {folderId, comment?})`; root upload sends neither
      field.
- [x] Detail shows all metadata and the attached notes; empty and 404
      states are honest (reason shown, section not hidden).
- [x] Existing folder create/rename/delete and file
      rename/sensitivity/delete behavior unchanged.
- [x] `npx --yes pnpm@12.14.0 typecheck && … lint && … test` green
      (150 suites / 1860 tests; ios/android/web tsc clean).
