# P6.0 — OAuth scopes match features that exist

Plan ref: `docs/clickstone.md` §0.5 (full-audit risk 9)
Status: done
Branch: `p6.0-oauth-scopes`

## Goal

Request only the scopes shipped features need (`SCOPES_NOW`) and diff
sessions against that set, with a reviewed `SCOPES_LATER` list that nothing
requests.

## Read first

- `docs/adr/0003-oauth-scopes-now-vs-later.md`
- `packages/fedi/src/mastodon/oauth.ts`, `src/state/session/store.ts`
- `docs/mastoapi-contract.md` §2.1 (scope set), `docs/DECISIONS.md` W4/W5

## Steps

- [x] 1. Split `MASTO_SCOPES` into `SCOPES_NOW` (shipped surfaces) and
      `SCOPES_LATER` (DMs, push, admin, reports, featured tags, favourites
      timeline); `MASTO_SCOPES` stays as a deprecated alias of NOW.
- [x] 2. Registration, authorize and password-grant defaults request
      `SCOPES_NOW.join(" ")` only.
- [x] 3. `scopeHealth` diffs against `SCOPES_NOW`; generations
      `pre-scopes`/`granular`/`current` and `needsUpgrade` unchanged in
      shape; LATER scopes never cause an upgrade.
- [x] 4. Tests: requested scope string == NOW and contains no LATER scope;
      scopeHealth matrix (umbrella-only → `pre-scopes` + `needsUpgrade`;
      all NOW → `current`; one NOW missing → exactly that scope; missing
      LATER only → `current`).
- [x] 5. ADR 0003 recorded (umbrellas kept with evidence; Akkoma and
      Mastodon consequences stated).

## Acceptance

- [x] requested/registered scope string equals `SCOPES_NOW.join(" ")`, no
      `write:reports` / `push` / `admin:read`
- [x] scopeHealth tests above
- [x] no session-clearing/revocation behavior changed
- [x] `npx --yes pnpm@12.14.0 typecheck && lint && test` green
- [ ] live Akkoma/Mastodon re-probe of umbrella necessity: not verified
      (rig unavailable in this slice)

## Out of scope

- Per-flavor scope strings (granular-only Mastodon vs umbrella Akkoma) —
  follow-up in ADR 0003.
- Moving `write:reports` into NOW (slice 1.5 owns that) and any admin/push/
  DM scopes.
- Revoking, clearing or silently re-authorizing existing sessions, and any
  new UI (the existing `needsUpgrade` prompt is reused).
