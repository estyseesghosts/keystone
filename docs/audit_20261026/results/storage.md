# Storage audit — Keystone v2 (2026-10-26)

Scope: `src/storage/mmkv*.ts`, `src/storage/tokens*.ts`, SecureStore vault (`src/storage/vault.ts`), session envelope + `hydrate()` (`src/state/session/store.ts`, `packages/fedi/src/core/sessions.ts`), query-cache persister (`src/state/queries/Provider.tsx`, `src/state/queries/stale.ts`, `src/state/queries/persistPolicy.ts`), drafts/recents stores (`src/storage/drafts.ts`, `src/components/EmojiPicker/recents.ts`, `src/state/emojiPrefs.ts`), post-shadow store (`src/state/cache/*`), MiAuth/OAuth pending rows (`src/screens/LoginFlows.ts`, `packages/fedi/src/mastodon/oauth.ts`), storage/session schema versioning + downgrade behavior, `signOutEverywhere`, `settleInto`, `mergeChatMessage`, `setListMember`, optimistic writes (`src/state/queries/graph.ts`, `src/state/queries/composer.ts`, `src/state/queries/chat.ts`). Read-only audit: no source modified, nothing run on a device. Every claim below cites a read line; grep was used to confirm absence (`encryptionKey` has zero matches in `src`; `clearPendingAuth` has zero callers in `src`).

## Summary

The 2026-10-25 audit's twelve findings are almost all closed. Verified fixed: vault-key charset (hex keys + a test running the real SecureStore regex), native secret-free envelope, sign-out purge (per-session storage + memory + query cache, with an enumeration test), envelope backup + empty-write refusal, hydrate resurrection (serialize chain + re-reads), `signOutEverywhere` pointer clobber, persist allowlist + per-session split + size cap + shrink-retry, buster derived from `SCHEMA_VERSION` + `MODEL_SHAPE_HASH`, device forward-version pointer preservation, MiAuth boot sweep, draft pointer prefix, and typed write-failure results with a draft-autosave surface.

New findings this round: 7 (1 medium, 6 low). The theme is residue around the fixed items: the on-disk purge is defeated by in-memory pref caches that re-persist (S1, the one medium), the OAuth pending rows never got the MiAuth sweep treatment (S2), the new envelope guards have a bypass (S3), and the at-rest story is "backup vector closed, secrets out of the envelope, everything else plaintext" (S7, standing).

## Findings

### S1 (Medium): purged per-session prefs survive in module-level memory caches and can be re-persisted to disk

- Locations: `src/components/EmojiPicker/recents.ts:36-54` (recents `cache` Map), `src/state/emojiPrefs.ts:115-137` (favourites `cache` + `write`), `src/state/emojiPrefs.ts:74-99` (like-emoji, no cache but keyed the same), `src/state/queries/graph.ts:63-86` (`softMuteStore` `cache`), `src/state/session/purge.ts:134-142` (`purgeSessionMemory`).
- `purgeSessionStorage` deletes the MMKV keys (`purge.ts:118-129`), but none of the four stores has any invalidate/clear method (verified by full reads — no such export exists). `purgeSessionMemory` clears only the post shadow and stream stops.
- Consequence 1 (read): after sign-out, `list(removedId)` / `has(removedId, …)` still serve the removed account's recents, favourites, like-emoji, and soft-mutes from memory until process restart. Scoping is still per-session-id so account B never sees them, but the signed-out account's data is not gone.
- Consequence 2 (write): the caches are write-through from cached values. `touch()` (`recents.ts:49-53`) does `list()` (stale cache hit) → prepend → `setItem`, recreating the purged `keystone.emojirecents.<sid>` key. Same for favourites `toggle`/`remove` (`emojiPrefs.ts:140-146`) and `softMuteStore.set` (`graph.ts:77-79`, via fedi `writeSoftMute`). A single emoji tap or mute toggle after sign-out resurrects that key on disk.
- The enumeration test (`purge.test.ts:207`) asserts over MMKV + QueryClient only, so it passes despite this — memory caches are outside what it enumerates.
- Fix: add a `clearSession(sessionId)` (or `reset`) to each of the four stores deleting the cache entry, and call them from `purgeSessionMemory` next to `postShadowStore.clearSession`. Extend the enumeration test to read back through the real stores after purge.

### S2 (Low): abandoned OAuth pending rows (`keystodon_pending_oauth_*`) accumulate forever — no sweep

- Locations: `packages/fedi/src/mastodon/oauth.ts:230` (`PENDING_PREFIX`), `:232` (15-min max age), `:671-722` (`save`/`take`/`clear`); writers at `src/screens/LoginFlows.ts:224-231` (row holds origin, redirectUri, state, CSPRNG `codeVerifier`, scopes); boot sweep covers MiAuth only (`store.ts:959`, `LoginFlows.ts:321-364`).
- `takePendingAuth` deletes on read (`oauth.ts:688-694`), but a dismissed browser / never-completed flow never reads. `clearPendingAuth` has zero callers anywhere in `src` (verified by grep), and nothing enumerates `keystodon_pending_oauth_*` keys.
- Impact is bounded: `take` rejects rows older than 15 min (`oauth.ts:708`), and a `codeVerifier` without its `code` is useless, so this is unbounded key growth + verifier material at rest, not a credential leak. Fix: sweep at boot alongside `sweepStaleMisskeyPending` (same `keys()` seam, same 15-min bound), and map the prefix to a real scope in `scopeForStorageKey` (`storageEvents.ts:29-43` currently yields `misc` for it).

### S3 (Low): `rewriteEnvelopeRows` bypasses the envelope's downgrade/corruption guards

- Locations: `src/state/session/store.ts:405-412` (direct `storage.setItem(SESSIONS_KEY, …)`); guards live in `writeStore` (`packages/fedi/src/core/sessions.ts:369-397`: newer-version refusal at `:374-375`, unreadable-empty-write refusal at `:377-385`, stale-`.bak` cleanup at `:388-393`).
- The only production caller is the `hydrateSecure` scrub rewrite (`store.ts:561-573`). Post-migration envelopes are tokenless so the scrub rarely fires, but when it does on a newer-version envelope it downgrades the version field to 1 unconditionally — exactly what `writeStore` refuses to do. `isNewerVersionEnvelope` (`sessions.ts:302-307`) is never consulted by `store.ts` (absent from its import block at `store.ts:1-26`).
- `STORE_VERSION` is still 1, so this bites only on a future bump or a corrupt-envelope-plus-scrub sequence. Fix: route the scrub rewrite through `writeStore` (or replicate the version check + refuse-empty-over-unreadable rule), as already flagged in `state/logs/2026-10-25-repair25-x1.3.md:38`.

### S4 (Low): `signOutEverywhere` unconditionally wipes the whole in-memory query cache, including a session added mid-flight

- Location: `src/state/session/store.ts:906-947`. The per-session loop carefully re-reads and spares sessions added during revokes (`:915-931`), and the pointer logic spares a surviving active id (`:936-943`) — but `await clearAllQueries()` at `:932` runs regardless and cancels + clears every query, including the newcomer's just-fetched data.
- Transient and self-healing (refetch repopulates; persisted blobs for the new session are untouched — `purgeAllPersistedSessions` only removes manifest + listed blobs). Fix: run `clearAllQueries()` only when no sessions remain; otherwise `removeSessionQueries` for the removed ids (already done per id in the loop).

### S5 (Low): `removePersistedClient` orphans per-session blobs when the manifest is missing or corrupt

- Location: `src/state/queries/persistPolicy.ts:543-570`. The per-session sweep happens only inside a successful manifest parse (`:545-560`); a corrupt manifest falls into `catch` and only the manifest key is removed, and a missing manifest skips enumeration entirely — `keystone-query-cache.<sid>` blobs stay on disk.
- Harmless to correctness: `restoreMergedClient` (`:484-536`) requires a `sessions` array and otherwise falls through to the legacy parse which yields null for these shapes, so orphans never restore. It is permanent disk waste, because the `gone` prune in `serializeSplitPersistedClient` (`:452-459`) also needs a previous manifest to discover them. Fix: on manifest-miss/corrupt, enumerate `keys()` for the `${QUERY_PERSIST_KEY}.` prefix and delete matches.

### S6 (Low): recents/emojiPrefs discard the seam's typed write-failure result (residual S12)

- Locations: `src/components/EmojiPicker/recents.ts:52` (`touch` ignores the `setItem` boolean), `src/state/emojiPrefs.ts:48-54` (`writeText` is void, ignores it).
- `createMmkvStore.setItem` emits `storageWriteFailed` only on throw (`mmkv.ts:32-43`); a `false` return (quota/locked store on exotic backings) is silently swallowed by these two callers, whose in-memory caches then pretend the value persisted. Draft autosave surfaces failure and the session envelope keeps its memory copy, so this is the last silent pair. Fix: check the boolean and emit (the seam already provides `emitStorageWriteFailed`).

### S7 (Low, standing): at-rest plaintext model — secrets fixed, everything else still MMKV-plaintext

- `encryptionKey` has zero matches in `src` (verified by grep): `sharedMmkv()` is `new MMKV({id: 'keystone'})` (`mmkv.ts:66-70`). Closed since last time: `android.allowBackup: false` (`app.config.js:49-55`) with the hardening plugin owning the `files/mmkv/` exclusion, and the native envelope is secret-free (`sessionWithoutToken` at `store.ts:824`, vault round-trip + stale-entry-clearing at `tokens.ts:47-101`, app-secret migration + scrub at `store.ts:582-613` / `oauth.ts:373-407`).
- What remains plaintext on disk by design: explicitly-saved DM drafts (autosave skips direct drafts with a notice per `Composer.test.tsx:1405`, but explicit Save persists `text` + `visibleUserIds` via `drafts.ts:275-293`), public-timeline first-page blobs (allowlisted, stripped, 2 MB-capped), device prefs, and the forensic `.bak` rows.
- One `.bak` nuance worth recording: `keystone_sessions.bak` is cleared only by a healthy explicit-empty write (`sessions.ts:388-393`). A backup taken while the envelope still carried tokens (pre-migration) survives the vault-migration scrub, because the scrub path (`rewriteEnvelopeRows`) has no `.bak` cleanup — token bytes rest until the last account is removed. Fix when convenient: scrub-then-clear-`.bak` once the envelope verifies tokenless.
- Web is unchanged and owner-accepted: token in the envelope (`store.ts:845-850`) plus a second copy in the MMKV vault (`tokens.web.ts:29-35`), and the web MMKV shim is `localStorage`-backed (verified `node_modules/react-native-mmkv/src/createMMKV.web.ts:57-59`). Documented release blocker per `tokens.web.ts:6-13` (decision D2) — restated here, not a new finding.

## Looked solid

- Envelope versioning on the guarded path: newer-version read-only mode + `isNewerVersionEnvelope` predicate (`sessions.ts:302-317`), corrupt/dropped-row backups write-once (`:309-336`), empty-over-unreadable refusal (`:369-397`).
- `hydrate()` races: the `serialize` chain (`store.ts:366-373`) plus per-step re-reads in `hydrateSecure` (`:490-499`), basis-checked scrub rewrite (`:561-573`), and the web overlay with basis + refresh-wins logic (`:979-1033`).
- Sign-out purge surface: single `sessionScopedKeys` list (`purge.ts:71-83`) covering drafts/live/legacy-pointers/bak, account scope, soft-mute, recents, favourites, like-emoji, homeTab (format matches the owner at `Home.tsx:42-44`), and the per-session persist blob + manifest prune (`purge.ts:118-129`); memory half clears shadow + streams (`:134-142`); query half cancels-then-removes per session (`:219-236`); enumeration test pins it (`purge.test.ts:183-227`); `signOutEverywhere` revokes in parallel and spares added sessions (`store.test.ts:388-433` coverage per `purge.test.ts:388+`).
- Persist policy: default-deny kind map (`persistPolicy.ts:54-91`), descriptor-gated feeds (`:100-152`), success-only dehydrate gate (`:158-161`), private-row stripping (`:206-248`), first-page trim + 2 MB shrink-largest-first + shrink-retry (`:301-346`), per-session split blobs with unchanged-skip and pruned-removals (`:396-474`), corrupt-restore→null so boot goes cold (`:484-536`, `Provider.tsx:199-201`).
- Optimistic-write isolation: sessionId-first keys enforced by constructor (`keys.ts:13-18`); `patchPostInCaches` touches only `queryKey[0] === sessionId` (`patch.ts:118-120`); post-action queues keyed per session+post+kind with the calling session's backend rebound on reuse (`postActions.ts:89-96`); `settleInto` projects one field (`post-shadow.ts:86-104`) and each merge is base-guarded per field so fresh server data wins (`post-shadow.ts:179-249`); graph toggles derive optimistic/rollback views from the confirmed value with cancel-then-write (`graph.ts:126-162,176-215`); `resolveFollowRequest` cancels, snapshots `before`, and rolls back to it (`graph.ts:280-300`); `setListMember` is capability-gated (`graph.ts:302-307`); `insertCreatedPost` never routes DMs/followers-only/replies into shared timelines (`composer.ts:132-171`); `mergeChatMessage` is pure, id-deduped, first-page prepend (`chat.ts:283-297`) writing only never-persisted chat kinds.
- Pending-flow hygiene (MiAuth half): boot sweep of stale/mismatched rows (`LoginFlows.ts:321-364`, hooked at `store.ts:959`) and take-and-delete replay guard with expiry (`LoginFlows.ts:377-407`).
- Draft durability: 30-day TTL enforced on read and swept at boot (`drafts.ts:13-18,150-197`), 25-cap with `evictedOldest` surfaced (`:275-286`), write failures returned not thrown (`:212-232`), unreadable-overwrite backups on a suffix-free key (`:89-95`), legacy `.open` migration (`:97-118`).
- Device/account schema: forward-version device payloads keep the mirror pointer with default prefs (`schema.ts:120-132`), every overwrite of an unreadable blob backs up first (`schema.ts:172-214`, `index.ts:91-108`, `drafts.ts:212-232`), and the mirror can never conjure a ghost session (`resolveActiveId`, `store.ts:200-208`).
