# Security audit — Keystone v2 (2026-10-26)

Scope: auth (OAuth/PKCE in `packages/fedi/src/mastodon/oauth.ts`, MiAuth in `packages/fedi/src/misskey/*` + `src/screens/Login.tsx` + `AuthCallback.tsx` + `LoginFlows.ts` + `MastodonCallback.ts` + `PasswordSignin.ts`), token storage (`src/storage/tokens*.ts`, `src/storage/mmkv.ts`, `src/storage/vault.ts`, `src/state/session/store.ts`), cross-origin handling (`packages/fedi/src/core/http.ts`, `packages/fedi/src/mastodon/client.ts`, `packages/fedi/src/misskey/client.ts`, `packages/fedi/src/misskey/external.ts`), deep links (`app.config.js`, AndroidManifest, iOS entitlements/Info.plist), link/HTML/MFM rendering sinks (grep `innerHTML|dangerouslySetInnerHTML|WebView|eval|new Function|Linking.openURL|window.open`), instance-URL handling (`normalizeOrigin`, `normalizeHost`, `safeUrl`/`safeHttpUrl`, `isPublicHttpsUrl`), native config (`android/app/build.gradle`, manifests, `plugins/withAndroidHardening.js`), query-cache persistence (`src/state/queries/persistPolicy.ts`, `Provider.tsx`), logging redaction (`src/lib/logger.ts`), secrets (grep, `.gitignore`), dependencies (`package.json`). No source modified. Only issues verified in code are listed. Did NOT run `pnpm audit`.

## Summary

The core design is strong and materially better than the 2026-10-25 baseline: six of the ten prior findings are fixed in code. Tokens are bound to a session/origin at the transport layer, absolute URLs are same-origin-checked before any request, every credentialed fetch uses `redirect: 'manual'` with a typed 3xx refusal, content is parsed to an allow-listed AST with a vetted-URL gate, CSPRNG has no `Math.random` fallback in any security path, and no `innerHTML`/`eval`/WebView exists. No secrets are committed. The remaining weaknesses are at the edges: release builds are still signed with the debug keystore, the MiAuth callback still rides a custom scheme (accepted risk, ADR 0012, mitigations in place), the web build still keeps tokens in localStorage-backed MMKV, three call sites still open URLs without going through the vetted `openExternal` helper, and a dev-only cleartext hatch plus permissive debug manifests remain to be release-verified on device.

Fixed since 2026-10-25 (verified in code, not re-listed as findings): plaintext MMKV token duplication on native (secret-free envelope + SecureStore vault + boot migration/scrub), Android `allowBackup`, redirect-following with body-carried `i` tokens, the unvetted chat-attachment open, `openExternal` accepting any string, `http://` for public hosts, PKCE/state/session-id randomness fallbacks, and the unfiltered persisted query cache. See `## Looked solid` for the exact lines.

No critical findings. 1 high, 1 medium, 3 low.

## Findings

### H1 (high) Android release build signed with the debug keystore
- `android/app/build.gradle:100-107` (only a `debug` signing config exists, `storePassword 'android'`), `android/app/build.gradle:112-115` (release `signingConfig signingConfigs.debug`).
- Scenario: any release/side-loaded APK is signed by a publicly known key. Anyone can build a same-signature update/impersonating app. Combined with the `keystone://` scheme (M1), signature-based trust does not exist.
- Fix: dedicated release keystore supplied via CI secrets / gradle properties; fail the release build when absent. Note `android/` is generated by prebuild (`app.config.js`), so fix in a config plugin. Unchanged since 2026-10-25.

### M1 (medium) Misskey MiAuth callback uses a custom scheme with no binding secret (accepted risk, ADR 0012)
- `src/screens/LoginFlows.ts:425-444` (`startMisskeyMiAuth` passes `redirectUri` as the MiAuth `callback`), `src/screens/Login.tsx:78-83` (`redirectUriFor` → `Linking.createURL` → `keystone://` on native), `app.config.js:25` (`scheme: 'keystone'`), `android/app/src/main/AndroidManifest.xml:26-32` (broad `keystone` + `exp+keystone` intent filters), `src/screens/AuthCallback.tsx:134-141` (take-once pending row, replay guard).
- Mitigations verified present and correct: CSPRNG session ids with no fallback (`packages/fedi/src/misskey/external.ts:137-139` → `packages/fedi/src/core/random.ts:77-89`, throws `errors.crypto.unavailable`), 15-minute single-use pending rows (`src/screens/LoginFlows.ts:305-310, 377-407`), origin binding (`src/screens/AuthCallback.tsx:71-76`) plus verified-account host check (`src/screens/AuthCallback.tsx:82-88`, enforced at all three completion sites), narrowed `intentFilters` (`app.config.js:63-70`, `autoVerify: false`). The config itself notes the narrowed filter is depth, not a boundary: the top-level `scheme` still generates its broad filter alongside (`app.config.js:57-62`).
- Scenario: on Android another app can register `keystone://` and receive the redirect `?session=<uuid>`. `miauth/<session>/check` needs no other secret, so the interceptor can redeem the approved token before/without the legitimate app (take-once makes it a race, not a prevention). Mastodon is protected by PKCE; MiAuth has no equivalent.
- Fix: use https App Links / Universal Links for the callback (needs signing identity + domain — recorded as out of scope in `docs/adr/0012-miauth-callback-risk.md`). Device-check: confirm no third-party app on the test device claims `keystone://`.

### L1 (low) Web build stores tokens in localStorage-backed MMKV
- `src/storage/tokens.web.ts:20-44` (vault is MMKV, dev-grade by comment), `src/state/session/store.ts:845-849` (web path: envelope keeps the token copy), owner decision D2.
- Scenario: any XSS exfiltrates all sessions' tokens. The native envelope is now secret-free, so this is web-only.
- Fix: document as release blocker for web (as today) or move to in-memory + httpOnly proxy; add CSP at the host. Unchanged since 2026-10-25.

### L2 (low) Three call sites open URLs without going through the vetted `openExternal` helper
- `src/components/Notification/NotificationRow.tsx:355-357` (`void Linking.openURL(href)`), `src/components/Post/PostCard.tsx:517` (`resolved ?? uri`, raw server `uri` fallback), `src/components/Post/PostCard.tsx:522` and `:832` (direct `Linking.openURL`).
- Safe today: AST hrefs are vetted at parse (`packages/fedi/src/core/content/ast.ts:325-351`), the remote-post resolver only yields http(s) page URLs (`packages/fedi/src/misskey/remotepost.ts:50-73`), menu-model URLs pass `safeHttpUrl` (`src/components/Post/menuModel.ts:186-191`), and misleading labels confirm before opening (`src/components/RichText.tsx:384-421`). But these call sites bypass the defence-in-depth gate every other surface uses (`openExternal` vets inside, `src/components/richtext/mentionRouting.ts:29-39`), so a future parser or resolver bypass becomes a direct arbitrary-scheme open.
- Fix: route all four through `openExternal` (or `vettedExternalUrl`).

### L3 (low) Residual dev-only cleartext surface; `Math.random` survives only in non-security ids
- `packages/fedi/src/core/http.ts:207-211` (`__DEV__` hatch permits http for non-local hosts in dev builds; closed under `NODE_ENV=test`), `android/app/src/debug/AndroidManifest.xml:6` (`usesCleartextTraffic="true"`, debug only), debug network-security-config permissive (`plugins/withAndroidHardening.js:66-79`, release denies by default at `:50-63`).
- `Math.random` remains only for non-security identifiers (`src/state/queries/composer.ts:856` upload key, `src/storage/drafts.ts:312` draft id) — grep verified no randomness fallback in any security path.
- Fix: none in code (hatch is dev-only by construction); device-check needed: release build denies http to a public host and allows it to `10.0.2.2`/localhost.

## Looked solid

- Transport: `requestJson` has no token parameter, rejects cross-origin absolute URLs and non-`/` paths before I/O, `redirect: 'manual'` with a typed 3xx refusal, `credentials: 'omit'` (`packages/fedi/src/core/http.ts:285-373`). Same guard in the Mastodon client (`packages/fedi/src/mastodon/client.ts:347-362`), Misskey client (`packages/fedi/src/misskey/client.ts:395-410`, upload path re-checks same-origin at `:385-391`), external direct POSTs (`packages/fedi/src/misskey/external.ts:188-203`), remote-post resolution (`packages/fedi/src/misskey/remotepost.ts:118-127`), nodeinfo/detect (`packages/fedi/src/core/detect.ts:822`) and link preview (`packages/fedi/src/api/linkpreview.ts:215`). Grep for `redirect:` in `packages/fedi/src` finds only `manual`.
- Origins: `normalizeOrigin` defaults to https and rejects non-local http (`packages/fedi/src/core/http.ts:103-143`, `rejectNonLocalHttp` at `:217-226` with local-host allowlist at `:165-196`); `normalizeHost` shares the policy (`packages/fedi/src/misskey/external.ts:121-128`). iOS ATS strict (`ios/Keystone/Info.plist:47-53`, `NSAllowsArbitraryLoads=false`, local networking only); Android release denies cleartext with a local-only NSC (`android/app/src/main/AndroidManifest.xml:16`, `plugins/withAndroidHardening.js:40-63`).
- Randomness: every security path (PKCE verifier/state via `packages/fedi/src/mastodon/oauth.ts:538-540`, MiAuth session ids, OAuth pending rows) goes through `packages/fedi/src/core/random.ts`, which throws `errors.crypto.unavailable` without a CSPRNG — no `Math.random` fallback anywhere in a security path (grep verified). Native installs the CSPRNG at boot when absent (`src/platform/polyfills.ts:23-39`).
- Token storage (native): hex-encoded SecureStore-valid vault keys (`src/storage/tokens.ts:31-34`, pinned by `src/storage/tokens.test.ts:50-58`), secret-free envelope writes (`src/state/session/store.ts:824`), boot migration with read-back verification and scrub (`src/state/session/store.ts:485-575`), app-secret migration out of MMKV rows (`packages/fedi/src/mastodon/oauth.ts:328-407`, `src/state/session/store.ts:582-613`), vault failures surfaced to the UI instead of silent plaintext fallback (`src/state/session/store.ts:522-533`), full per-session wipe on remove/sign-out (`src/state/session/store.ts:868-898, 906-947`, `src/state/session/purge.ts`). MMKV still has no `encryptionKey` (`src/storage/mmkv.ts:66-71`) — acceptable now that the native envelope carries no secrets.
- OAuth: PKCE S256 (pure-TS fallback where `crypto.subtle` is unavailable) + state, pending flows read-and-delete with 15-minute expiry (replay guard), origin taken from the pending row not the URL, token verified before store (`packages/fedi/src/mastodon/oauth.ts:618-634, 687-713`, `src/screens/LoginFlows.ts:209-283`, `src/screens/MastodonCallback.ts:29-56`). Passwords live only in screen locals and the grant call (`src/screens/PasswordSignin.ts`, `src/screens/LoginFlows.ts:120-189`); the full-authority native credential is memory-only for the mint exchange. MiAuth requests least-privilege per-endpoint permissions (`packages/fedi/src/misskey/auth.ts:104-153`).
- Content: HTML via htmlparser2 and MFM via mfm-js into one AST; `safeUrl` allows only http/https/mailto, strips credentials, rejects relative/protocol-relative/`javascript:`/`data:` and over-long or control-char inputs (`packages/fedi/src/core/content/ast.ts:301-351`); images restricted to http(s) (`safeHttpUrl`). One `RichText` renders everywhere (`src/components/RichText.tsx`); `openExternal` re-vets every target (`src/components/richtext/mentionRouting.ts:22-39`); link/image/avatar gates verified at `src/components/Post/LinkCard.tsx:63-69`, `src/screens/explore/NewsTab.tsx:34-39`, `src/screens/ChatThread.tsx:56-61`, `src/components/Post/PostMediaGrid.tsx:601-615`, `src/components/Profile/UserHoverCard.tsx:198-202`. Outbound page fetches (unfurl, remote-post) require public https (`packages/fedi/src/core/urlPolicy.ts:237`, `packages/fedi/src/misskey/remotepost.ts:118`). No `innerHTML`, `dangerouslySetInnerHTML`, `eval`, `new Function`, WebView or `javascript:` sinks in `src/` or `packages/` (grep verified — only comments naming them).
- Query cache: default-deny persist policy (only public timelines/profiles/emoji/metadata/`me`), private `direct`/`followers` rows stripped, first page only, size-capped, split one MMKV key per sessionId, mutations never persisted (`src/state/queries/persistPolicy.ts:54-152, 206-260`, wired via `shouldDehydrateQuery` in `src/state/queries/Provider.tsx:197`).

- Logging: endpoint-only dev logger with `stripTokens`/`redactUrl` redaction of bearer/`i`/secret shapes (`src/lib/logger.ts:73-99`); `HttpError.path` documented token-free (`packages/fedi/src/core/http.ts:70-71`); `console.*` only in the gated dev sink (`src/lib/logger.ts:187-190`).
- Secrets/config: no keys/secrets tracked (grep — `client_secret` appears only in runtime vault logic, tests, and local probe scripts); `.gitignore` covers `.env*`, `*.keystore`, `*.jks`, `*.p8`, `*.p12`. No `postinstall` script; dependencies are a small Expo-pinned set (`package.json:46-86`). Did not run `pnpm audit` (not verified).
- Device-check needs (not verifiable statically): release APK/AAB free of `RECORD_AUDIO`/`SYSTEM_ALERT_WINDOW`/`CAMERA` and signed by the release key (H1); release denies cleartext to public hosts (L3); `adb backup` refuses (M2 fix); SecureStore accessibility/biometric options are defaults (`src/storage/tokens.ts` sets no `requireAuthentication` — standard for bearer tokens, confirm acceptable); no third-party app claims `keystone://` on the test device (M1).
