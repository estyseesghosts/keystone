## Summary

- i18n coverage is much improved: 131 of 153 non-test `.tsx` files reference Lingui (`useLingui`/`useI18n`/`Trans`/`msg`/`` i18n._ ``); the 22 without are mostly presentational primitives with no user strings (see Looked solid). `plural()` is now used in 8+ sites. Error codes are localized via `src/lib/localeErrors.ts` (`FEDI_ERROR_MESSAGES: Record<FediErrorCode, …>`, exhaustive by typecheck).
- Time/number formatting is centralized in `src/locale/format.ts` (app-locale-bound `Intl.*`, no bare `toLocale*` calls remain in `src/`). Relative timestamps refresh via the shared minute ticker `src/locale/ticker.ts` (`useNow`, 30s interval, AppState-gated).
- Most prior a11y gaps are fixed: toasts announce (live region + `announceForAccessibility` + hover/focus pause), dialogs have modal semantics + single keyboard-layer Escape stack + focus in/out, `Heading` has `accessibilityRole="header"`, topic chips are labeled buttons, `faint` now passes AA on `bg` in both themes, `ErrorBoundary` (root/screen/row) exists and wraps both feed lists, composer inputs draw the shared `alf/focus` ring on web focus, hover cards open on keyboard focus, RTL has `I18nManager` + `writingDirection: auto` + dev rehearsal flag.
- Perf posture is reasonable: 4 `memo()` components (`PostCardView`, `Inline`, `Flow`, `ThreadRow`), `usePostActions` returns a memoized object with `useCallback` setters, `buildPostMenu` is `useMemo`-gated, FlatList tuning is consistent (`windowSize 7`, `initialNumToRender 6`, `maxToRenderPerBatch 8`, deliberate no-`getItemLayout`/no-`removeClippedSubviews` comments), client unfurl is single-flight + cached + tap-gated for non-public posts, media uses one `expo-image` wrapper (`AppImage`) and a single-global-player slot for video/gifv/audio.
- No `StatusBar` gap: `src/state/systemUI.ts:14-21` drives `StatusBar.setBarStyle`/`setBackgroundColor` from the theme. No `Image` vs `expo-image` split: all stills route through `AppImage` (`src/components/Image.tsx:7-40`). No MediaGrid duplication: one `PostMediaGrid` shared by `PostCard` and `PostQuote`.
- Verified remaining issues: 5 (1 medium, 4 low). Contrast ratios below are estimated from theme tokens — needs device check.

## Findings

### 1. [Medium] Poll expiry/foot labels and internals still carry untranslated English literals
`src/components/Post/PostPoll.tsx:58-76,237-241`
- `formatPollExpiry` returns `'closing soon'` (`:58`), `'in under a minute'` (`:60`), and English fallbacks `` `in ${min}m` `` (`:65`), `` `in ${hours}h` `` (`:73`), `` `on ${formatDate(...)}` `` (`:76`). The `Intl.RelativeTimeFormat` branches are locale-correct, but every fallback and both sub-minute labels are English-only, and `formatPollExpiry` is a pure helper with no `i18n` access so callers cannot translate its return.
- The foot row pushes bare `'multiple choice'` (`:237`), `'closed'` (`:238`), and `` `closes ${label}` `` (`:241`) — none wrapped in `i18n._`. Compare the adjacent vote/voter counts on `:233-236` which correctly use `plural()`.
- Scenario: a Japanese user sees `複数の選択肢` nowhere — the poll meta reads "3 votes · multiple choice · closes in 5m" in English inside an otherwise translated card.
- Fix: move these strings into the component (or pass `i18n` into `formatPollExpiry`), wrapping each in `msg` with `plural` where counts appear.

### 2. [Low] `Intl.DisplayNames(['en'])` hardcodes English in translation matching
`src/components/Post/translationPolicy.ts:55`
- `translationDiffers` resolves the viewer's language name with `new Intl.DisplayNames(['en'], {type: 'language'})`, so a server reporting `"Chinois"` (French display name) or any non-English name never matches, and the comparison label logic is English-centric. Behavior stays safe (unrecognized source shows the translation), but the match is locale-blind.
- Fix: pass the app locale (`resolveAppLocale`/`useI18n().locale`) as the `DisplayNames` locale, falling back to `'en'`. Needs device check across `ja`/`zh` tags.

### 3. [Low] Recommendation-debug numerals use `toFixed`, ignoring locale numerals
`src/components/Recommendations/RecommendationReasonDialog.tsx:63-122`, `src/components/Recommendations/RecommendationsSettingsOverlay.tsx:447,466`
- Score breakdown cells render `breakdown.score.toFixed(3)`, `row.raw.toFixed(2)`, `×${weight.toFixed(2)}`, `(prob*100).toFixed(1)%` etc. as raw Latin-numeral strings. `src/locale/format.ts:122-147` provides `formatNumber` for exactly this.
- Only a debug/explainer surface (the dialog title and captions are translated), so low severity — but a `hi`/`ar`-locale user gets unlocalized digits in an otherwise localized dialog.
- Fix: route debug numerals through `formatNumber(locale, n, {minimumFractionDigits, maximumFractionDigits})`.

### 4. [Low] `faint` still below AA on secondary surfaces; ~263 call sites need the non-essential-only discipline
`src/alf/themes.ts:32-35,47-49`, pinned by `src/alf/__tests__/themes.test.tsx:42-46`
- Light `faint` `#767676` (4.54:1 on `bg`) and dark `faint` `#8a8a8a` (5.47:1 on `bg`) now pass AA on `bg` — the prior failure is fixed. The contrast test allowlists three below-AA pairs: `light:faint on bgSoft`, `light:faint on raise`, `dark:faint on raise` (measured ~3.8–4.4:1), documented as "non-essential captions on secondary surfaces only".
- `color="faint"` appears ~263 times (`grep -c`), heaviest in `AdminInsight.tsx` (22), `Notifications.tsx`/`Note.tsx`/`ChatThread.tsx` (11 each). Spot-checked uses are captions/meta (e.g. `AdminInsight.tsx:156-176` denied/absent hints, `Note.tsx` timestamps) — consistent with non-essential. Any future essential label in `faint` on `bgSoft`/`raise` silently inherits the allowlist.
- Needs device check (estimated from tokens). Fix: keep the lint/test gate; audit new `faint` uses for essential text and prefer `muted`/`text` there (the `Button` disabled-label repair at `src/components/Button.tsx:38-48` is the model).

### 5. [Low] One physical `textAlign: 'right'` + absolute-positioned hover/popover geometry are RTL-brittle
`src/components/Recommendations/RecommendationReasonDialog.tsx:139`, `src/components/Profile/HoverPreview.tsx:184-452`, `src/components/Popup.tsx:65-304`
- The score table's numeric column uses `textAlign: 'right'` (`:139`) — physical, not logical. Under RTL it stays right-aligned while the reading direction flips. Trivial in a numeric table, but the codebase is otherwise logical (`paddingStart`/`paddingEnd` in `Lightbox.tsx:667-671`, `borderStartColor` in `RichText.tsx`, `writingDirection: 'auto'` for user content).
- `HoverPreview`/`Popup` position cards with physical `top`/`left`/`right` from `getBoundingClientRect` (`HoverPreview.tsx:184-193,441-452`; `Popup.tsx:155,277`). Correct on today's LTR-only catalogs (`en fr de zh ja hi yue` — all LTR, RTL only via the dev rehearsal flag `src/locale/i18n.ts:249-289`), but a future RTL catalog gets mirrored-clamped cards only if the anchor math flips.
- No shipped RTL locale, so future-risk only. Fix: `textAlign: 'right'` → keep for numerals with a comment, or use `locale`-aware alignment; note the anchor-flip requirement wherever the first RTL catalog lands.
