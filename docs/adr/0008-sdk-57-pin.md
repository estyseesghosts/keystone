# ADR 0008 — Pin SDK 57 native deps, drop Bluesky-mirror overrides

Date: 2026-10-24
Status: accepted
Plan ref: `docs/audit_20261024/repair.md` R2.3 (F1)

## Problem

`pnpm-workspace.yaml` overrides `react-native-reanimated` (4.7.1),
`react-native-worklets` (0.13.0), and `react-native-screens` (4.30.0)
past the Expo SDK 57 pins in `package.json` (4.5.1, 0.10.1, ~4.26.2),
so `npx expo install --check` flags exactly those three as misaligned.
The overrides were kept to mirror Bluesky (`docs/DECISIONS.md:170`),
but nothing in `src/` uses the newer APIs — and every future native
crash inside reanimated/screens/worklets would start with version
doubt. The keep-the-overrides call was recorded as intentional but
provisional ("full `--fix` alignment only if the newer stack breaks
again"); the audit (results/10 F1) forces the explicit decision.

## Options considered

1. Drop the three version overrides and ride the SDK 57 pins —
   `package.json` already declares the `--check`-expected versions, so
   this is a metadata-only change until the next `pnpm install`.
2. Keep the Bluesky-mirror overrides as intentional, with a standing
   crash-suspect note — rejected: we pay version doubt on every native
   stack trace for APIs nothing in `src/` imports.

## Decision

Option 1. `pnpm-workspace.yaml` keeps only the
`@react-native/babel-preset` override (matches the installed tree, not
flagged by `--check`); the three version overrides go. `src/` has zero
`reanimated` / `react-native-worklets` imports (verified by grep —
`no matches`), and `react-native-screens` is consumed only transitively
through React Navigation, so no app code depends on the newer behavior.
`react-responsive` (zero runtime imports — only "why we left" comments)
is removed from `package.json` in the same pass.

## Consequences

- Good: `expo install --check` is clean on these three; native crashes
  in animation/screens code are debugged against the SDK-tested matrix.
- Bad / accepted risk: if the newer stack fixed a latent bug we hit
  later, we re-pin deliberately with evidence (see follow-ups). Native
  bundle state is `not verified` until a device build runs — no device
  ran in this slice.
- Follow-ups: run `pnpm android` / `pnpm ios` on a device machine after
  the next `pnpm install` and paste the bundle output into the session
  log; re-verify the scene-lifecycle plugins after every SDK bump
  (existing rule, unchanged).
