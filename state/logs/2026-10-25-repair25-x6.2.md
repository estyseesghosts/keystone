## Decided (load-bearing, no ADR — all within existing contracts)

- Misskey per-file byte caps: no known `meta` field, so `maxImageBytes/VideoBytes` stay null and
  the heap bound applies (documented in code). Reading an invented field name risked wrong
  semantics (quota vs per-file cap).
- New poll-bound limit fields default to null (never enforce on a guess, F10 spirit); the only
  pinned numeric default kept is the existing Mastodon 300 s clamp (X4.3 test pins it).
- Misskey CW cap 100 (UTF-16, matching the file's existing conservative Misskey counting).
- F10: when limits are unverified, the char check yields to the server (`effectiveLimits`
  inflates `maxChars` to the measured count) in BOTH `buildPostDraft` calls in submit, and the
  Post button stays enabled; the counter still shows the numbers and a `msg` notice
  (`composer-limit-unverified`) replaces the "Over the limit" caption. Other validations
  (poll/recipients/schedule) still apply.
- Sensitive/language UI is family-gated (Mastodon always takes both params; no probe exists),
  with the picker additionally hidden when the server reports no languages.
- X6.1 regions untouched: edit submit path, edit busy gates, `isCloseDirty` edit branch,
  autosave edit guard, EditCloseDialog. Edit mode never emits sensitive/language (seeds carry
  neither). X6.5 keyboard regions untouched.
