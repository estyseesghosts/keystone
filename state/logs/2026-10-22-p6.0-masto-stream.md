# 2026-10-22 — p6.0 Mastodon streaming safety — agent (subagent)

Branch: `p6.0-masto-stream`
Goal: put the Mastodon token in `Sec-WebSocket-Protocol`, handle ping/pong,
`kill` + `filters_changed`, bound reconnects (10s ack, stop after 5 fast
closes) with an honest dead state, and refuse a cross-scheme streaming
origin (`docs/clickstone.md` §0.1).

Did:

- `packages/fedi/src/mastodon/stream.ts`
  - Auth is now the subprotocol pair `["Bearer", <token>]`:
    `WebSocketFactory = (url, protocols?) => MastoSocket`, default factory
    `new WebSocket(url, ["Bearer", token])`. `streamUrl` lost its token
    parameter entirely; there is no `access_token` anywhere. Protocols come
    from the resolved dial only, so the token still reaches one origin.
  - `ping` (bare text, Akkoma) → `socket.send("pong")`, never routed as an
    event; a defensive `{event:"ping"}` frame answers the same way.
    `MastoSocket` gained an optional `send` (mocks without it stay silent).
  - `kill` → `stopEntry`: closes the socket, clears timers, marks the entry
    `dead`, state `stopped`, and schedules nothing. Subscriptions survive so
    the badge can offer a retry.
  - `filters_changed` → handle-level `onFiltersChanged(handler)` set; the
    frame never falls through to event routing.
  - Reconnect breaker: 10s `CONNECT_ACK_TIMEOUT_MS` watchdog per dial (a
    socket that never opens/`connected`-acks is a failure: closed and sent
    through the same failure path); `MAX_FAST_CLOSES = 5` consecutive
    closes within `FAST_CLOSE_MS = 10s` of open (or never opened) → `dead`
    + `stopped`, no further dial. A connection that stayed up resets the
    count, so ordinary reconnects behave exactly as before.
  - `retry()` clears the breaker (`dead=false`, `fastCloses=0`,
    `attempt=0`) and re-dials every live entry; returns false when there was
    nothing to dial.
  - Scheme pin: `streamingOriginAllowed(origin, advertised)` +
    `resolveStreamingBase(origin, advertised)` — an advertisement is only
    dialed when its scheme matches the session origin's `ws(s)` mapping
    (`https`→`wss`, `http`→`ws`); otherwise the session origin mapping is
    used. Split host stays allowed. `streamUrl` uses the resolved base.
  - `overall()` reports `stopped` when any entry is dead (and none is
    connected); `channelStatusOf` maps it to `unavailable`.
- `packages/fedi/src/mastodon/instance.ts`
  - `normalizeStreamingOrigin(raw, sessionOrigin?)`: the advertised origin is
    dropped (null) when its scheme disagrees with the session origin, so the
    capability record never carries a host the client must refuse.
    `fetchInstanceCapabilities` passes `origin` for both the v2 and v1
    advertisements.
- `packages/fedi/src/core/backend.ts`
  - `StreamState` gained `"stopped"` (the honest dead state). Never emitted
    by the Misskey pool — additive only.
  - `StreamHandle` gained optional `retry?()` and `onFiltersChanged?()` so
    each family opts in; nothing becomes required.
- `src/components/StreamBadge.tsx`: `stopped` renders “Live updates stopped”
  with the Retry button (error keeps its existing label). No infinite
  “Reconnecting…”, no fake live label.
- `src/state/streaming.ts`: `FeedLive.retry()` forwards to `handle.retry()`
  and `useFeedLive.resubscribe()` prefers it (remounts only for handles
  without retry, e.g. the Misskey pool). `useFeedLive` subscribes
  `handle.onFiltersChanged` → `client.invalidateQueries(serverFiltersQueryKey(sessionId))`
  (filters are server-owned; invalidate, never patch) and unsubscribes on
  every teardown path.
- Tests: rewrote `packages/fedi/test/mastodon-stream.test.ts` (header auth,
  scheme pin, ping, kill, filters_changed, 10s ack, 5-close breaker, retry,
  breaker reset after a healthy connection), added a scheme-pin case to
  `mastodon-instance.test.ts`, updated the old `streamUrl` token/URL
  assertions in `mastodon-w8-rows.test.ts`, added `FeedLive.retry()` to
  `src/state/streaming.test.ts` and a `stopped` badge test to
  `src/screens/HomeFeed.live.test.tsx`.

Decided (→ ADR or DECISIONS entry if load-bearing):

- Additive `StreamState = … | "stopped"` + optional `StreamHandle.retry?` /
  `onFiltersChanged?` instead of overloading `error` (which still means “a
  reconnect is scheduled”). Widening a union is type-safe; UI switch sites
  are exhaustive only where they read a state string, and `StreamBadge` is
  the only renderer. Candidate DECISIONS line for the coordinator (not
  edited here, per instructions): “Mastodon stream dead state = `stopped`;
  retry via `StreamHandle.retry?()`”.
- No SSE fallback and no per-post socket in this slice (`clickstone.md`
  §0.1 explicitly defers both).
- Scheme pin is enforced twice (discovery + dial) so a stale/misplaced
  capability record cannot leak a token to a differently-schemed host.
