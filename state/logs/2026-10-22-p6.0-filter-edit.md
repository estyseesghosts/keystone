# 2026-10-22 — p6.0 filter edit must not destroy keywords — subagent (DeepSeek V4.1 Flash)

Branch: `p6.0-filter-edit`
Goal: Mastodon v2 filters are groups of keywords; `list()` must expose
all of them and `update()` must write all of them back (no dropped
sibling, no reorder, no flag loss).

## Did

- `packages/fedi/src/core/backend.ts`
  - New `FilterKeyword {id, keyword, wholeWord}`; `Filter.keywords:
    FilterKeyword[]` (server order, never empty while a phrase exists).
    `phrase`/`wholeWord` stay as the primary (first) keyword so existing
    callers and the UI did not change shape.
  - `FiltersApi.update` doc now pins the in-place rewrite contract.
- `packages/fedi/src/mastodon/backend.ts`
  - `adaptV2FilterRow` maps EVERY keyword (`keywords[0]` is only the
    primary), keeps ids and `whole_word`; a keyword-less payload falls
    back to the title as `[title]` (never invents siblings).
  - `adaptV1FilterRow` maps its single keyword as `[phrase]` using the
    filter's own id (v1 row == keyword).
  - `update()` v2 path: read-then-PUT now writes
    `{id, keyword: phrase, whole_word}` for the primary and
    `{id, keyword, whole_word}` verbatim for every sibling; nothing is
    appended, reordered or sent as a bare `{id}`.
  - Group `title`: a custom title (≠ old primary keyword) is preserved;
    an auto-derived/absent one follows the phrase (the old code always
    renamed the group to the phrase).
  - `create()` unchanged (one keyword per group, as before).
- `src/components/Settings/FiltersSection.tsx`
  - Row shows all keywords joined with `", "`.
  - Edit field edits the primary keyword and, for a multi-keyword group,
    names the siblings that are kept ("Editing the first keyword. The
    rest of this group stay as they are: beta").
  - v1 rows render and edit exactly one phrase as before.
- `src/state/queries/moderation.ts`
  - `serverFilterWordsOf` enforces every keyword of a hide-action group
    (keywords OR server-side, groups union client-side); previously only
    the primary was enforced. Same single-keyword AND group shape.
- Tests: `packages/fedi/test/mastodon-w4-rows.test.ts` new
  `MD3-keywords` block (5 tests), `mastodon-w8-rows.test.ts` fixture row
  now has two keywords, `FiltersSection.test.tsx` multi-keyword row/edit
  test + stateful fake follows the backend contract,
  `moderation.test.ts` group-enforcement test, `Settings.test.tsx`
  fixtures carry `keywords`.
- `packages/fedi/test/fixtures/mastodon/filter-v2.json` now carries a
  second keyword (`spoilers`, `whole_word: false`).

## Failing-first proof (new tests on the unfixed code)

`npx --yes pnpm@12.14.0 test mastodon-w4-rows`

```
  MD3-keywords — v2 group edit keeps every keyword
    ✕ list() exposes every keyword, not just the first (1 ms)
    ✕ update() PUTs every keyword with its id and whole_word, and returns them all (2 ms)
    ✕ update() keeps each sibling keyword's own flag and order (3 keywords) (1 ms)
    ✕ keeps a custom group title instead of renaming it to the phrase (1 ms)
    ✕ v1 stays one keyword: list exposes [phrase] and update PUTs no keyword list
Test Suites: 1 failed, 1 total
Tests:       5 failed, 17 passed, 22 total
```

Two of the failures are the bug itself:

```
  ● list() exposes every keyword, not just the first
    Expected: [{"id": "k1", "keyword": "alpha", "wholeWord": false}, {"id": "k2", "keyword": "beta", "wholeWord": true}]
    Received: undefined

  ● update() PUTs every keyword with its id and whole_word, and returns them all
    - Expected  - 2
    + Received  + 0
        Object {
          "id": "k2",
    -     "keyword": "beta",
    -     "whole_word": true,
        },
```

(i.e. the old PUT sent `[{id:"k1",keyword:"alpha edited",whole_word:false},{id:"k2"}]`
— the sibling's text and flag were destroyed.)

## Decided

- Domain shape: structured `keywords: FilterKeyword[]` rather than
  `string[]`, because the PUT needs the keyword ids and the per-keyword
  `wholeWord` (a string list would lose both and force a re-read anyway).
  `phrase`/`wholeWord` remain the primary aliases — no caller breaks.
- No new optional full-list argument on `update()`: the slice allows
  keeping the single-phrase API, and a validated `opts.keywords` path
  would be dead code while the UI only edits the primary. The write path
  still round-trips every sibling.
- Primary `whole_word` still comes from `opts.wholeWord` (`=== true`),
  exactly as before; siblings keep their own flags. The UI passes the
  row's flag, so it round-trips through the screen.
- Group title: preserve a custom title, follow the phrase only when the
  title was auto-derived (equal to the old primary) or missing. Avoids a
  new destructive field while keeping our own single-keyword filters'
  titles in sync.
- Feed enforcement in `serverFilterWordsOf` updated to all keywords — a
  hidden group whose second keyword silently stopped filtering would be
  the same data loss seen from the reader's side.
- New UI string is a `msg` macro whose catalog entry does not exist yet;
  the slice forbids locale-catalog edits, so it renders English source
  until the next `intl:extract`. No fake/placeholder text was added.
