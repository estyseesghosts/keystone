Goal: Composer with gated features, reply/quote, polls, media upload, drafts, autocomplete, posting only through the active session.

Did:

- Reused existing backends: `createPost`, `uploadMedia`, `scheduled.create`, `search.suggest*`, `customEmojis` already existed; new fedi logic is one file, `api/composer.ts`.
- Pure composer logic: server limits (Misskey `POST /api/meta` `maxNoteTextLength`, no token; Mastodon `fetchInstanceCapabilities`), char counting (Mastodon URLs 23, remote mention as `@user`; Misskey UTF-16), visibility options per family with `raw` passthrough, replies never widen audience, `composeGates`, `buildPostDraft` (drops disabled features, poll expiry ms for Misskey vs seconds for Mastodon), autocomplete trigger parsing.
- `src/storage/drafts.ts`: drafts per session id (`keystone.drafts.<sessionId>`), zod-validated, corrupt rows dropped. Attachments are not persisted.
- `src/state/queries/composer.ts`: `useComposeLimits`, `useSessionCustomEmojis` (keys sessionId-first), `useCreatePost` (posts via that session's backend; on success `insertCreatedPost` prepends to that session's `timeline|home`, `timeline|social`, author's `user|<id>|posts|replies` feeds and bumps parent reply / quoted-quote counts; scheduled posts are not inserted), `uploadAll`/`useUploads`.
- UI: `src/components/Composer/{Composer,Autocomplete,Chip,pickMedia,index}`, `src/screens/Compose.tsx` (modal route; params replyToId, quoteId, draftId).
- Media: files are staged with alt text and uploaded at submit (neither family can edit description afterwards through Backend), sequentially, per-file status uploading/done/error, retry on submit; Mastodon async-processing poll is already in `uploadMedia`. Progress is per file, not bytes.
