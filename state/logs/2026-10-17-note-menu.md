## What changed

- `frontend/src/styles/global.css` — `.notemenu*` rules after

- `docs/frontend-plan.md` — new checklist section (slice 1 built, 2–4
  open).

## Deviations from the plan (deliberate)

- **Translate** reason: plan says "no translation endpoint". False here:
  `notes/translate` is live and runs automatically (`api/translate.ts`,
  `TranslatableText`). Row stays disabled, reason now "translation runs
  automatically, no per-post toggle yet".
- **Search this user's notes** reason: plan says "no search route yet".
  `docs/api-surface.md` records note search as implemented but refused by
  the servers (`UNAVAILABLE`). Reason now says restricted, not missing.
- **View on remote instance (user)**: plan opens `user.url`, but
  `UserLite` (feed notes) carries no profile URL. Guessing one from
  host + username would fabricate a link (AGENTS.md §5 forbids it). The
  row shows for remote accounts and stays disabled with the reason.
- **Placement**: right-aligned to the trigger, not left-aligned as the
  plan's `AccountCard` pattern suggests, because the trigger sits at the
  right of the action row. Clamped inside the viewport by measuring the
  rendered menu.
- **Scroll dismissal** ignores scrolls inside the menus. Otherwise the
  overflow-scrolling menu would close itself as soon as it was scrolled.
- **Submenu focus**: opened by click/Enter/ArrowRight it moves focus into
  the submenu; hover-open does not steal focus.
