Decided (load-bearing):

- **`i/read-announcement` is the Misskey-family dismiss, not
  `announcements/dismiss`.** The brief named `announcements/dismiss`; the
  verified Misskey/Sharkey/Catodon checkouts all expose
  `i/read-announcement {announcementId}` (`write:account`) and none has a
  `dismiss` endpoint. The domain verb stays `dismiss` (both families
  "mark this notice read"), the wire call is the verified endpoint.
  Recorded here rather than silently inventing a route.
- **`Announcement.content` is the SOURCE, not pre-rendered text.** AGENTS
  §6 requires one allow-listed AST; Misskey `text` is MFM and Mastodon
  `content` is server HTML, so the model carries `Content {mfm|html,
  plain}` and the screen parses through `contentFromMfm`/`contentFromHtml`
  into the single `RichText`. The old `text: string` field (never
  produced) is replaced.
- **`title` is nullable.** Mastodon announcements have no title and no
  severity; null is the honest value — no synthesized "Server
  announcement" heading.
- **`isRead` is tri-state.** `read` exists only for an authenticated
  Mastodon request and `isRead` only for an authenticated Misskey pack;
  `null` means "not reported", and the screen says "Read state unknown"
  rather than guessing "Unread".
- **`list` keeps the declared `Promise<Announcement[]>` shape.** Mastodon
  has no cursor (the whole published list) and Misskey's list is small;
  the screen fetches one page of 50 and never offers a "load more" that
  Mastodon could not honour. Paging params still pass through for the
  Misskey family.
- **Dismiss means "read", so the row stays.** Both servers only record a
  read mark (`AnnouncementRead` / `AnnouncementMute`); neither removes the
  row from the list. The screen mirrors exactly that (state flips to
  Read, row remains) instead of pretending the notice disappeared.
- **404/405 is absence, not error.** List 404 → the "not available on
  this server" state; dismiss 404 → the button is disabled with the
  reason. This is the same contract as the notification dismiss and the
  rules endpoint (clickstone §1.11/§1.5).
- **`announcements` is not a Misskey-only surface.** Both families serve
  it, so the sidebar/account-menu entry is capability-gated rather than
  family-gated, and the entry is hidden signed out (dismiss needs auth and
  the screen is auth-first, consistent with Channels/Antennas).
