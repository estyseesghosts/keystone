Goal: Repair §X1.5 — a token revoked while the app runs is detected and the session is dropped (after confirmation), not left as an empty signed-in shell.

Did:

- Step 1 — `src/state/queries/Provider.tsx` (`onError` ONLY): `createAppQueryClient` now builds the client with a `QueryCache` and a `MutationCache`. Both filter to `isRuntime401` (`ApiError` status 401 ONLY — 403/network/5xx never route) and extract the session id from a sessionId-first key (`sessionIdFromKey`: null for missing/non-string/empty/`'signed-out'` heads). Query path uses `query.queryKey[0]`; mutation path uses `mutation.options.mutationKey[0]` (mutations carry no session key today and no new keys are introduced per X0.1, so key-less mutations are ignored by design — never mis-attributed to the active session in a multi-account tree). Known sessions only (a store-list lookup; ghosts never reach the network). A per-client `pending` map dedupes bursts so concurrent 401s enqueue one verify and one toast. `QueryProvider` wires the real store via `useOptionalSessionStore` (Root already nests `QueryProvider` inside `SessionProvider`; bare trees get an unwired client; an injected `client` keeps its own caches — existing tests unaffected).
- Step 2 — `src/state/session/store.ts` (`verifySession` only): single-flight (concurrent calls share one `me()`) + 30 s cool-down qualified by live token (a verify that just ran is reused; a re-added session with a new token verifies fresh). Only a fresh `me()` 401 — the second 401 after the triggering query/mutation — drops the session via the existing `dropLocal` (X1.2 purge path: query purge + storage purge + memory purge + D3). 403 → `forbidden`, network → `network`, other → `error`: all remembered for the cool-down, none drop.
- Step 3 — Lazy verify on switch: no code change — `switch` stays synchronous and network-free (pinned by test). An inactive session verifies when the user switches to it via its next failure through the step-1 path (verified end-to-end through hooks in the wiring test).
- Step 4 — UI: when the verify reports `cleared`, the handler shows one toast via Lingui `msg` — `Signed out of ${label}: session expired` (label = displayName ?? accountId) — and navigates to `Login` when no sessions remain (`navigationRef`, guarded by `isReady`). Boot drops (`Root` → `verifyActive`) are untouched and stay silent, as before — the toast covers the runtime path this slice owns.
