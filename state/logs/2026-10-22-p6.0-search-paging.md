# 2026-10-22 — p6.0 search paging — subagent

Branch: `p6.0-search-paging` (base `a809e3e`)
Goal: Mastodon v2 search (`Backend.search.posts` / `.accounts`) pages via
the Link header instead of ending on page 1 (clickstone §0.2).

Did:

- `packages/fedi/src/mastodon/pagination.ts`
  - `Cursors` gained `offset?: number` (v2 search / trends page-number
    paging); `withCursors` emits it and `cursorsFromUrl` reads it as a
    number. Id-cursor endpoints are unaffected (they never receive offset
    links; the param is ignored if one appears).
  - Extracted `linkContinuation(headers, origin, rel)` and added
    `prevContinuation` beside `nextContinuation`. Both still prefer the
    server's exact same-origin URL and fall back to carrying cursor PARAMS
    onto the session origin; a cross-origin link with no recognized cursor
    still ends the feed.
- `packages/fedi/src/mastodon/endpoints.ts`
  - `SearchResult` now carries `continuation: Continuation | null` and
    `prev: Continuation | null`, both parsed from the Link header.
  - `searchV2` takes `SearchV2Options` (`type`, `limit`, `continuation`,
    explicit `offset`/`maxId`/`minId`). A same-origin continuation URL is
    replayed verbatim with no extra params; a cross-origin one is rebuilt
    on the session origin from its cursor params; a fresh request sends
    `q` + type + limit/offset/max_id/min_id. Empty query with no
    continuation still returns the empty result without a request.
- `packages/fedi/src/mastodon/backend.ts`
  - `search.posts` → `searchV2(..., {type: "statuses", ...pageOpts(opts)})`;
    `search.accounts` → `type: "accounts"`. Typed search is required:
    upstream `SearchService` pins combined (type-less) search to offset 0
    (`app/services/search_service.rb`: `@offset = options[:type].blank? ?
    0 : …`), so only a typed search can page.
  - `toSearchPage` maps the page with the standard §5 rule: `end` iff no
    next continuation or an empty page. No `length < limit`, no invented
    cursor. `suggestTags`/`suggestAccounts` unchanged (single request).
- Tests (+7):
  - `packages/fedi/test/mastodon-backend.test.ts`: new describe
    "MastodonBackend search paging" — posts next-Link then end; account
    next-Link then end; cross-origin next Link carries `{offset, limit}`
    onto `/api/v2/search`; full page with no Link ⇒ `end`/`cursor: null`;
    empty page with a next Link still ends; `searchV2` exposes the
    Link-derived `prev`.
  - `packages/fedi/test/misskey-backend.test.ts`: regression that
    `search.posts` pages `untilId` and `sinceId` (Misskey code untouched).

Decided (log-only; no ADR — contained data-layer fix, no plan reversal):

- Link is the only cursor source for search. Real Mastodon's
  `/api/v2/search` currently emits no `Link` (`app/controllers/api/v2/
  search_controller.rb` never calls `set_pagination_headers`; Akkoma
  `search2` also answers plain JSON), so those servers stay one page —
  contract §5 forbids inventing a next page from item counts. Servers /
  proxies that do emit `rel="next"` (the shapes the audit's Link-parsing
  requirement targets) now page correctly.
- `offset` lives in the shared `Cursors` rather than a search-local parser:
  `cursorsFromUrl` is the one place that reads Link params, and rebuild-on-
  origin needs the offset. No other endpoint emits `offset` links.
- `prev` is exposed on `SearchResult` but not on core `Page` (the model
  carries only a next cursor); no UI change in this slice.
