## Did

### Bug 1 — uploads always root

- `packages/fedi/src/misskey/client.ts`: `UploadOptions` gains
  `folderId?: string | null` and `force?: boolean`. `upload()` appends
  `folderId` only when a non-empty id is given (null/"" = root, never put
  on the wire) and `force` only when defined.
- `packages/fedi/src/core/backend.ts`: new `UploadMediaOpts`
  (`isSensitive`, `comment`, `folderId`, `force`); `Backend.uploadMedia`
  uses it. Mastodon's implementation keeps its narrower signature — Drive
  does not exist there.
- `packages/fedi/src/misskey/backend.ts` `uploadMedia`: builds the
  multipart options explicitly, dropping a null `folderId` (root) instead
  of forwarding it.
- `src/state/queries/composer.ts`: `UploadTarget {folderId?, force?}`;
  `uploadOne`/`uploadAll`/`useUploads` take an optional target and forward
  it. `useUploads` reads the target through a ref so a fresh object
  literal does not re-create `ensureUploaded`.
- `src/components/Composer/Composer.tsx`: new optional
  `uploadFolderId` prop, passed to `useUploads({folderId: uploadFolderId})`.
  Default `null` = root.
- Drive screen: unchanged. It has no upload action in this slice (Wave 1
  slice 1.10 owns "upload from the Drive screen" and folder targeting);
  inventing a picker here would be the new UI 0.7 forbids. The wire is
  ready for it — see Deviations.

### Bug 2 — `notes/edit` dropped noQuote and could not touch polls

- `packages/fedi/src/misskey/noteEdit.ts`: `EditNoteParams` gains
  `noQuote?: boolean` and `poll?: PollDraft | null` (the exact create
  shape: `choices`, `multiple`, `expiredAfter`, `expiresAt`). `editNote`
  forwards params verbatim and does not catch anything — a 4xx reaches
  the caller as the typed `ApiError`.
- `packages/fedi/src/misskey/backend.ts` `editPost`: sends `noQuote`
  whenever the draft defines it (so `false` can lift an earlier refusal)
  and the create-shaped `poll` when present.

### Bug 3 — `notes/like` seeded false

- `packages/fedi/src/misskey/backend.ts`: removed the MK13
  `if (capabilities.like === "unsupported" && opts.origin)
  seedLikeSupport(opts.origin, false)` block.
- `packages/fedi/src/misskey/like.ts`: removed `seedLikeSupport` and its
  static-seed rationale. Only a real 404/`UNKNOWN_API_ENDPOINT` caches
  `false`; a successful call caches `true`. `LikeUnsupportedError` and
  the per-origin cache stay. `src/state/cache/postActions.ts` is
  untouched: its `isSupported() !== false` gate now means "unprobed →
  try the endpoint", and after a real 404 the ❤ fallback is taken
  without wire traffic.

### Bug 4 — schedule/draft lists were `untilId`-only

- `packages/fedi/src/misskey/schedule.ts` / `serverDrafts.ts`:
  `listScheduledNotes(call, limit, untilId?, sinceId?)` /
  `listServerDrafts(call, limit, untilId?, sinceId?)`.
- `packages/fedi/src/misskey/backend.ts`: `scheduled.list` and
  `serverDrafts.list` pass both `cursor.untilId` and `cursor.sinceId`
  (decodeCursor already carried both), so pull-to-refresh can request
  newer rows.

## Decided (→ ADR or DECISIONS entry if load-bearing)

- `folderId`/`force` are omit-when-unset fields, never empty strings: a
  null/empty folder id means the Drive root and is not sent, because
  Sharkey rejects unknown/empty fields. Same rule as the rest of the
  Misskey param builder.
- No static like-support seed at all. A flavor label cannot prove the
  endpoint absent (backports exist), so `isSupported()` stays `null` until
  a real answer; only a 404/`UNKNOWN_API_ENDPOINT` caches `false`.
- Edit forwards `noQuote` whenever defined (create only sends `true`), so
  an edit can lift a refusal. Poll edits are never pre-stripped.
