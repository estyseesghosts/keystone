Did:

- `src/components/Settings/MutesSection.tsx`
  - `WordField`: replaced the seed-at-most-once refs with account-identity-aware reseed. A `lastAccountId` ref tracks the `me?.id` the field was seeded from. A change away from a known account id (including to `null` while the next account loads) resets `edited`, marks seeded state, and reseeds from the new `me` (or clears to `''`). Same-account arrivals keep the original semantics: seed at most once, never over an in-progress edit.
  - `MutesSection`: added a `useEffect(..., [backend])` that sets `me` to `null` on backend identity change, so B's screen clears instead of seeding from (and briefly displaying) A's stale record while the refetch resolves. Same-account `refreshKey` refetches do not clear, so in-progress edits in sibling fields survive a save.
- `src/components/Settings/MutesSection.test.tsx`
  - Added suite `Mutes section word fields reseed on account switch (R0.1)` with test `shows account B text after a switch and saves B payload to the B backend`: two sessions (alice/bob) in one store, per-account mocked backends with distinct mute text; starts on A, asserts `alpha`/`hard-a`, switches session + backend together, asserts textarea values become `beta`/`hard-b`, presses save, asserts `backendB.updateProfile` called with `{ext: {mutedWords: [['beta']]}}` and `backendA.updateProfile` never called.

Decided (→ no ADR: no load-bearing reversal, fix is local to the slice):

- Deviation from the slice's preferred fix (`key={session.id}` on each `WordField`): keying alone does NOT fix production. On a switch, `MutesSection.me` still holds A's record until `backend.me()` resolves, so a remount keyed by session reseeds from stale A and the (reset-by-remount) seeded ref then pins A's text — the corruption survives. The identity-aware reseed handles both the simultaneous swap (test) and the lagged refetch (production). No key added; focus behavior unchanged (no remounts at all).
- No text is copied across accounts: on a switch the old value is discarded (`''` while loading, then B's server text). The server write path is untouched — still the active session's backend.
