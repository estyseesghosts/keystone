Decided (→ load-bearing notes, no ADR — no storage/model change):

- Abort error identity is `kind: 'aborted'` + `errors.network.aborted`,
  status 0, on both families (`ApiError` on Misskey so `kind` exists).
- `retry.ts` gained `isAbortedError`/`abortedError`/`throwIfAborted` and the
  retry predicate returns false for aborts. This is outside the literal
  "queryFn bodies ONLY" region but is the only in-scope place that can
  implement "never retried" (recorded as a trivial deviation).
- Same-file helper plumbing (`fetchFeedPage`, `fetchPostThread`,
  `useInfinitePages`, `useChatMessages`, `fetchIdSet`/`useIdSet` signatures)
  was widened to carry the signal (trivial deviation, same files).
- Admin sections, filters, report rules, interests, custom emojis, compose
  limits, `showRoom`, conversation `get`, `editHistory`, list membership:
  pre-abort only — their backend modules are owned by other slices, so
  mid-flight abort there is not yet wired; unmount still reverts the query.
- Mastodon 202-processing poll loop (`getMedia`) left un-threaded (X7.4
  owns upload timeouts); the initial upload POST carries the signal.
- `callPublic` unchanged (auth flows, no queryFn uses it). `Provider.tsx`,
  `store.ts`, screens, streams, uploads controller untouched per scope.
