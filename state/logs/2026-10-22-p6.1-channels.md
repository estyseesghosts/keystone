Decided (→ log only; no ADR, no plan reversal):

- Directory = `channels/search` with `query: ""` instead of
  `channels/featured`. `featured` is a fixed top-10 ordered by
  `lastNotedAt` with no cursor, which cannot satisfy the
  `ChannelsApi.list(): Page<Channel>` contract; `search` with an empty
  query is exactly the same server-side "all non-archived channels,
  id-desc" listing, and it pages both ways. `featured` is not wired.
- No `allowPartial` is sent on `channels/timeline`: the reference client's
  paginator sends only `channelId` + cursor params, and the cross-backend
  param rule (AGENTS §5) keeps our timeline calls to `{limit, sinceId,
  untilId}` + ids.
- `Channel.isFollowing` is `boolean | null | undefined`: `null` = the
  server reported unknown (a pack without `me`, or a fork that omits the
  field), `undefined` = the field was absent. The UI gates the follow
  toggle on a known boolean and shows the reason otherwise — never a
  guessed `false`.
- The channel live channel is public (no credential needed), so
  `needsAuth: false`; only home/hybrid/userList/antenna stay
  auth-required. The Mastodon family's `streamNameFor` returns `null` for
  a channel source, so its mount stands down to paging — no URL-token
  code was touched.
- Forks whose channel surface is unverified (`pinetree`, `catodon`) keep
  `channels: "unknown"`; the direct `/channels` route renders the honest
  unavailable state there even though the module exists. `unknown` never
  unlocks (AGENTS §6).
- `followed()` is data-layer + tested this slice; the directory shows a
  `following` badge from the `search` pack instead of a second tab. A
  "Following" tab is a later UI slice, not a data gap.
