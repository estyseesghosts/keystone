Decided (load-bearing):

- **Omit defaults, never send empty arrays/false.** Verified against
  `ReportsController#report_params` + `ReportService#call`: the server
  fills the same defaults, so omitting an unset field cannot change
  behavior; sending `status_ids: []` / `forward: false` would only add
  noise. Chosen category is sent as chosen (including `other`).
- **`rule_ids` implies `category: "violation"` on the wire.** The server
  forces it anyway; sending a contradictory category would be a lie the
  server silently overwrites.
- **Honest typed result over silent drops.** `ReportResult.unsupported`
  names every chooser field a family could not carry, with a reason;
  Misskey returns all four when passed. The UI never passes them there.
- **Rules are Mastodon-family only and read from v1 `instance/rules`.**
  No v2 rules endpoint exists; Akkoma serves none → status 404 hides the
  step with a reason. Cache key is session-scoped.
- **`write:reports` now in NOW (ADR 0003 follow-up b).** Existing granular
  sessions surface `needsUpgrade` / `stale-scopes` with exactly
  `['write:reports']`; no session is revoked, and new authorizations
  request the scope. ADR 0003's consequence text already anticipated this,
  so no ADR edit was needed.
- **Misskey keeps the required reason; Mastodon does not.** The Misskey
  endpoint rejects an empty comment (minLength 1), the Mastodon endpoint
  accepts a report with only a status/category. Refuse/disable where the
  server requires it, allow elsewhere.
- **Last-used category is device-local** (`keystone.lastreportcategory`),
  like feed-tab/emoji prefs; it is a convenience default, not account data.
- **One reported status, not a picker.** The reporter acts on one post;
  `PostHandlers` sends that post as `status_ids: [id]` and the chooser
  never invents additional statuses.
