## Decided (→ DECISIONS.md transcription by orchestrator)

- `expo-secure-store@58.0.2` added (root dep; peer `expo: "*"` — no SDK pin needed).
- Token layering: sync MMKV seam holds the envelope WITH its token copy (core logic unchanged on both platforms); async vault above it holds the OS-secured per-(sessionId, origin) copy — writes go to both, reads prefer the vault (`hydrate()`). Envelope copy is the sync fallback, never removed.
- Active-session source of truth = core envelope; device `activeSessionId` is a write-through mirror, read ONLY as boot fallback (`resolveActiveId`), never the reverse.
- `.web.ts` split for the vault (repo's existing platform-file pattern) over a runtime `Platform.OS` check — keeps `expo-secure-store` out of the web bundle/typecheck entirely.
- Provider NOT mounted in `Root.tsx` (Phase 3 wiring owns app boot; mounting now would change boot for all existing suites).
- `apiCall` on a Mastodon-family active throws 404 `UNSUPPORTED_FAMILY` before any I/O (Misskey endpoints have no Mastodon path; caller uses `activeBackend`).
