## Decided (no ADR — interface addition follows the W1/0.7 pattern)

- `showFile`/`attachedNotes` are required `DriveApi` members: the only
  backend with a `drive` module is the Misskey family, and it implements
  both. Servers whose endpoint 404s at runtime are covered by the UI's
  visible-reason states, not by a new capability flag (no flag exists for
  individual drive endpoints, and adding one would widen `Capabilities`
  beyond this slice).
- Detail keeps the destination visible when the endpoint 404s: the row's
  metadata still renders and the notes section shows its reason. Nothing
  is hidden and no control is inert.
- Upload is stage-then-confirm (not pick-immediately-upload) so the
  optional `comment` can be typed before the bytes are sent; the picker is
  the composer's existing seam, no new dependency.
- Root target = `folderId` omitted everywhere (`files`, `uploadMedia`);
  the backend never sends an empty/null field (Sharkey unknown-field and
  empty-field rules).
- Upload refresh uses a ref to the latest `load` so a folder switch during
  an in-flight upload still refreshes the folder the viewer is looking at.
