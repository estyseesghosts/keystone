## Did (E1)

- `src/components/Post/ReactionChips.tsx`: `ChipArt` routes every custom key through
  `CustomEmojiGlyph` (entry URL → tolerant packed lookup via `reactions.urls` →
  session listing → remote/author-host tables → literal `:code:`, never fabricated).
  `:name@host:` with null packed URL now resolves via the store (was literal forever);
  bare Mastodon-family shortcodes with URLs take the same path; pure unicode unchanged.
  New optional `sessionId`/`authorHost` props (explicit wins, else active session via
  `useOptionalActiveSession`, else packed-only). Removed the single-shot `Image`+`failed`
  state (the glyph retries down the chain instead of sticking literal on first failure).
- `src/components/Post/PostQuote.tsx` (emoji sessionId-threading ONLY, zero layout change):
  new optional `sessionId` prop + active-session fallback, threaded into `DisplayName`
  and into `RichText` with `authorHost={quote.author.host}`. Before, quote bodies were
  packed-only (remote codes literal) and quote names relied on the implicit fallback.
- No `packages/fedi` change needed: `parseEmojiCode`/`lookupPackedEmojis` already exported;
  `adaptReactions` exact-key misses are absorbed by the tolerant glyph lookup downstream.
- `DisplayName.tsx`, `EmojiImage.tsx`, `customEmojiStores.ts`: read, no change — the chain
  (packed → remote-host → author-host → session listing → literal) was already correct there.

## Did (E5)

- `CompactComposer.tsx` (picker-embed region only): emoji-button press now
  `Keyboard.dismiss()`es before opening the popup. Reason: the popup is a separate Modal
  window — on Android the soft keyboard covers Modal content (no adjustResize there) and
  the first tap is swallowed; dismissing anchors against the full window. Search re-opens
  the keyboard on focus. Web-neutral.
- `ComposerSections.tsx` (`SuggestEmojiSection` only): same dismiss when the full-composer
  `Dialog` opens (`useEffect` on `c.pickingEmoji`).
- `EmojiPicker/EmojiPicker.tsx`: `FlatList` gains `nestedScrollEnabled` (it renders inside
  `AnchoredPopup`'s `ScrollView`; without this the inner list never gets the gesture on
  Android) — `keyboardShouldPersistTaps="handled"` kept. No layout/measurement change.
- Deliberately NOT touched: `Popup.tsx`/`Dialog.tsx` (not owned). Residual risks live there:
  outer `ScrollView` in `AnchoredPopup` has no `keyboardShouldPersistTaps`, so with the
  keyboard up for search the first cell tap may still dismiss-first on native; and
  `measureInWindow` under an open keyboard can mis-anchor — the dismiss-first mitigation
  above covers the common path. Popup owner / coordinator call on whether to change those.
