# 2026-10-15 — Stonekey: Keystone × Misskey/Sharkey

Goal: fix Keystone per `docs/stonekey_ui.md` + `docs/stonekey_backend.md` so
Misskey and Sharkey both work as backends. No browser in this environment:
proof is API-transport probes (the exact HTTP the browser performs, through
Keystone's own Vite proxies) + static source checks + build.

## What changed

Backend-only switch (both servers):
- `packages/backend/src/server/ServerService.ts` (+ built output) in
  `/root/fedifedifedi/misskey` and `/root/fedifedifedi/sharkey`: skip
  `clientServerService.createServer` when `KEYSTONE_BACKEND_ONLY=1`.
  Servers restarted with the flag. Verified: `GET /` → 404 (was 200 HTML),
  `GET /miauth/*` → 404, `POST /api/meta` → 200, on both.

Keystone frontend (`frontend/`):
- `src/api/backend.ts` (new): backend select (`VITE_KEYSTONE_BACKEND`),
  per-backend token keys (session isolation), scoped permission set.
- `src/api/client.ts`: shared `postJson` core, `apiCallPublic`, `signinFlow`
  (`/api/signin-flow`), `mintAppToken` (gen-token + miauth check).
- `src/state/auth.tsx` + `src/routes/Login.tsx`: Keystone-owned login —
  form → Keystone permission screen → scoped app token. No redirects, temp
  credential never persisted.
- `vite.config.ts`: `KEYSTONE_BACKEND_URL` proxy target + `/proxy`,
  `/streaming` entries; `frontend/.env.misskey` (`:3101`), `.env.sharkey` (`:3102`).
- stonekey_ui fixes: persistent single-fire repost; pagination dedupe +
  end-state + retry-older; profile links (notes, notifications, mentions via
  cached `users/show`); mobile account strip out of the bottom nav; media by
  MIME (img/video/audio/file + failure fallback); quote embed without nested
  anchors; readable notification labels + timestamps + paging; profile notes
  (`users/notes`); reply threads (`notes/replies`, labeled partial);
  nested-button fixes.
- Docs: `README.md`, `AGENTS.md` (§§3,5 + layout/routes), `docs/api-surface.md`
  (verified matrix), `docs/frontend-plan.md`, `state/STATE.md` rewritten.

Doc corrections applied (finders verified against server sources):
- Native sign-in is `POST /api/signin-flow`, NOT `/api/signin` (404 on both).
- `notes/global-timeline`, `users/notes`, `notes/replies`, `notes/conversation`
  exist on both — supported, not unsupported.
- `i/notifications` has no `isRead`; `following/*` returns `UserLite`;
  timeline `include*Renotes` params are Misskey-only (never sent).
