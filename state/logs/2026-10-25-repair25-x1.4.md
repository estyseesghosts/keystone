## Follow-up — 5 own-test failures (coordinator-verified), implementation fixed

Scope this round: `persistPolicy.ts` only (test expectations untouched; no other file modified).

Root causes:

1. `shouldPersistQueryKey(['signed-out', 'post-feed', 'timeline|home'])` → true (and `['me', 'signed-out']` → true): the kind allowlist ran before any scope check, so a signed-out-scoped key with an allowlisted kind persisted. Fix: reject up front when `sessionIdOfKey(key) == null` — same rule as the X0.1 key lint (session-first or nothing).
2. Manifest read-back empty: `serializeSplitPersistedClient` returned the manifest JSON but never stored it — storing was left to Provider's `setItem`, which direct-call tests bypass. Fix: serialize stores the manifest under `key` itself (skip-if-unchanged); Provider's `setItem` rewrite is now idempotent.
3. `restoreMergedClient` → null: same root cause as 2 (no manifest in store). No restore-code change needed beyond the timestamp below.
4. `removePersistedClient` left blobs: same root cause as 2 (manifest sweep found nothing). No remove-code change needed.
5. Latent second defect found while fixing 2 (would have broken the skip-write test): the blob envelope carried the per-save `Date.now()` and the manifest carried `timestamp`, so identical data still produced different bytes. Fix: manifest is now `{buster, sessions}` (no timestamp); blob skip-comparison is timestamp-insensitive (`{buster, clientState}` compare, `dehydratedAt` normalised to 0); a data change rewrites that session's blob with the fresh timestamp, and restore uses the freshest blob time for maxAge.
