# 2026-10-22 — P6.0 OAuth scopes now vs later — subagent (deepseek-v4.1-flash)

Branch: `p6.0-oauth-scopes`
Goal: request only scopes for features that actually exist; diff
`scopeHealth` against that set; record the umbrella decision in an ADR.

Did:

- Split `packages/fedi/src/mastodon/oauth.ts` scope list into `SCOPES_NOW`
  (umbrellas `read write follow` + the 21 granular scopes backing shipped
  screens) and `SCOPES_LATER` (`write:reports`, `read:conversations`,
  `write:conversations`, `push`, `admin:read`, `admin:write`,
  `read:featured_tags`, `write:featured_tags`, `read:favourites`).
  Nothing requests LATER.
- `registerApp` / `getCachedApp` defaults now `SCOPES_NOW.join(" ")`; the
  authorize URL and the Akkoma password grant already ride the cached
  app's `scopes`, so all three request exactly NOW. `FALLBACK_SCOPES`
  (`read write follow`) unchanged and is a subset of NOW.
- `MASTO_SCOPES` kept as a deprecated alias of `SCOPES_NOW` so
  out-of-tree/parallel-slice imports keep compiling (no in-tree user left;
  `src/state/session/store.ts` now imports `SCOPES_NOW`).
- `scopeHealth` diffs the cached app against `SCOPES_NOW` only; generation
  logic unchanged (`pre-scopes` umbrella-only, `granular` granular-but-
  missing-a-NOW-scope, `current`). Type comments for
  `SessionScopeGeneration` / `SessionScopeHealth` updated: LATER scopes are
  never an upgrade reason and never appear in `missingScopes`.
- Tests: new `packages/fedi/test/mastodon-oauth-scopes.test.ts` (NOW/LATER
  disjoint, registered/authorize/password-grant strings ==
  `SCOPES_NOW.join(" ")` and contain no LATER scope, shipped scopes still
  requested, cached app with a LATER scope not reused, pre-split cached app
  reused → old sessions untouched). `src/state/session/store.test.ts`
  scopeHealth matrix extended (all NOW → `current`; NOW+LATER → `current`;
  missing LATER only → no upgrade; one NOW missing → exactly `write:filters`;
  umbrella-only → `pre-scopes` + `needsUpgrade`; granular-only → missing
  umbrellas).
- `docs/adr/0003-oauth-scopes-now-vs-later.md` + `docs/tasks/p6.0-oauth-scopes.md`.

Decided (→ ADR 0003):

- Keep `read`/`write`/`follow` in NOW. Evidence: Akkoma
  `/api/v1/suggestions` 403s a granular-only token while the umbrella form
  succeeds (live probe 2026-10-21, `docs/DECISIONS.md` W5) and Explore's
  suggestions/trends/news are shipped; W4's live 403s show Akkoma's scope
  checks are umbrella-sensitive. Dropping them would break shipped Akkoma
  behavior and the rig was not available to re-probe every endpoint.
- Accepted risk recorded: Mastodon expands `read`/`write` to every
  `read:*`/`write:*`, so Mastodon tokens still carry DM/report authority
  via the umbrellas. Follow-up: per-flavor scope strings once Akkoma's
  umbrella endpoints are mapped.
- `write:reports` stays in LATER; slice 1.5 moves it into NOW and reuses the
  existing `needsUpgrade` prompt. No session revocation/clearing in this
  slice, and no new UI.

Bluesky/other sources consulted: none needed for this slice (Bluesky has no
MastoAPI OAuth scope model). Grounding: `docs/mastoapi-contract.md` §2.1/§4,
