Decided (→ log only; no ADR, no plan reversal):

- Personal `/api/v1/domain_blocks` only. Admin domain blocks stay Wave 3.
- Tag mute = honest disabled row on the Tag screen (not a hidden row, not
  a client filter). A client-side substitute would mean authoring a
  server-side `#tag` keyword filter on the user's behalf (Mastodon
  `filters`), which is a different contract (contexts/expiry/text match)
  and would surface as an unexplained filter row; Misskey soft-mute is
  server-side `mutedWords` on the Misskey family only. Per clickstone
  §1.4 ("prefer the honest disabled row over inventing server state"),
  the gap is documented instead.
- Gating uses module presence + optional methods + runtime 404/405, not
  new `Capabilities` keys: `detect.ts`/`FEATURE_KEYS` untouched (capability
  table is architecture surface; this slice does not need it and `unknown`
  semantics stay intact).
- Featured tags: `POST /tags/:id/feature|unfeature` (newer Mastodon) with
  a 404/405-only fallback to `POST /featured_tags {name}` and
  `GET /featured_tags` → `DELETE /featured_tags/:id` (older Mastodon).
  Akkoma/Pleroma leave `featured*` undefined (source-verified absence) so
  the row is disabled-with-reason; an unknown flavor keeps the methods and
  degrades only if the server 404s at runtime.
- Unblock sends the domain as a DELETE query param (matches the reference
  web client and both controllers' `params[:domain]`).
- UI scope for featured tags is the Tag screen toggle + data-layer
  listing/delete; no new settings screen (clickstone: "smallest honest
  surface").
