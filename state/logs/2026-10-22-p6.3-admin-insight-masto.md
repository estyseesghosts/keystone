## Decided

- Scope strategy (i): `admin:read` LATER→NOW (the ADR 0003 mechanism —
  old tokens get the existing 0.5/0.8/0005 upgrade prompt, never
  revoked) AND appended to the Mastodon flavor string (the umbrella
  alone 403s). `admin:write` stays LATER (no mutations this slice);
  `read:conversations` still never requested. Authorize URL is
  `read write follow admin:read` (~345 chars, still <480 — pinned).
- Gating: capability flags stay `unknown` statically (no role inference
  in detect.ts per brief); the runtime gate is `adminInsightGate`
  (module present + family + flag not `unsupported` + `adminRoleOf` from
  verify_credentials via live `useMe`/sign-in cache). Sections
  additionally degrade on live 403/404 — the capability flag cannot go
  stale because it never claims the role.
- `mastodon/instance.ts` NOT touched: `fetchInstanceRules` already exists
  in `endpoints.ts`; peers/extended-description/activity live in the new
  `admin.ts` per the brief. No `instance.ts` change was needed.
