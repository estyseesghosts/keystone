# 2026-10-20 — P3.1 sign-in follow-up — agent

Branch: `p3.1-signin-functional`
Goal: make the keystonev2 UI sign-in functional — first-party (hosted
alongside a server) + third-party (external server), with a reachable entry
from every signed-out surface.

## Did

- Boot hosting: new `src/state/hosting.tsx` (`useHosting` bridge over the
  fedi singleton + `resolveAppHosting` boot probe); `Root.tsx` resolves
  `loadRuntimeConfig` → `resolveHosting` in the ready gate (failure resolves
  third-party, never a boot error).
- MiAuth browser sign-in in `LoginFlows.ts`: `startMisskeyMiAuth`
  (session id, pending row in appStorage, instance approval URL with
  `callback`), `pollMisskeyApproval` (check loop + `fetchExternalMe`
  verify-before-return, honest timeout), `takeMisskeyPending` (read+delete
  replay guard, 15-min expiry). No `packages/fedi` changes — the ported
  `misskey/external.ts` already covered it.
- `Login.tsx` rewritten hosting-aware (old Keystone `routes/Login.tsx`
  model, own code): first-party internal form (misskey-native / pinetree via
  existing password flow; password-grant + MFA for Akkoma/Pleroma; same-origin
  PKCE for vanilla Mastodon) vs third-party external (server entry → detect;
  Misskey = MiAuth browser only, password never asked; Mastodon = password
  grant when supported + browser OAuth otherwise). Mode tabs only when
  first-party and external accounts allowed.
- `AuthCallback.tsx`: handles MiAuth `?session=` (web + native deep link) —
  takes the pending row, short polls, detects flavor, stores
  (`miauth`/`third-party`) — alongside the unchanged Mastodon `code/state`
  path.
- Entry points: `src/navigationRef.ts` (root ref, no expo-linking at import
  time); `MainTabs` shows a Sign in tab while signed out (account tabs return
  on sign-in); web `LeftNav` mirrors it + always shows Settings;
  `SignInButton` (ref-based, renders nothing where no navigation is mounted)
  on FeedView/User/Notifications signed-out states.
- `Settings.tsx` is real now: `AccountSwitcher` (switch/sign-out/everywhere,
  add → Login). Native reaches it via "Accounts & settings" on the own
  profile; web via LeftNav.
- `docs/tasks/p3.1-signin-functional.md` + index row; DECISIONS row.

## Decided (-> DECISIONS)

- External Misskey = MiAuth browser only (old product rule: a typed password
  only ever goes to its own server). Internal/first-party Misskey/Pinetree =
  password (signin-flow → mint, Pinetree `signin` fallback unchanged).
- External Mastodon keeps password-grant when the capability is supported
  (Akkoma/Pleroma; P3.1 behavior) + browser OAuth otherwise; first-party
  vanilla Mastodon uses same-origin PKCE.
- First-party transport is direct same-origin fetch (no dev proxy in Expo);
  web-dev against a cross-origin rig server needs server CORS.
