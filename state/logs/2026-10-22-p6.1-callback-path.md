Decided (→ ADR/DECISIONS: none required; no ADR written):

- **The registered redirect URI did NOT change.** Web keeps
  `${origin}/auth/callback` at every base (exactly what v2 registered
  before this slice); native keeps `Linking.createURL('auth/callback')`.
  Therefore no instance re-registers (`getCachedApp` identity check
  untouched) and no migration consequence exists — so per the brief no
  `docs/adr/0004-*.md` was created. Instead the app accepts the v1 root
  path, which is the goal of §1.13 ("accept both").
- Alias as a ROUTE, not a rewrite. `rewriteLegacyPath` is for URLs whose
  target is a different screen (`/local` → `/network/local`); the callback
  is the same screen and must keep its own URL until the one-time params
  are consumed, so a `linkingScreens()` leaf + a second `Stack.Screen` is
  the honest shape.
- Callback paths are exempt from base stripping (in `stripShellBase`, not
  in the parser) because the v1 root URL can literally sit under a base
  prefix of the same name. The canonical base-prefixed form
  (`/keystone/auth/callback`) is longer and still strips normally, so no
  path is handled twice.
- Kept the path in the address bar on cleanup (only query/fragment are
  dropped) — under a base the browser must not lose its mount point, and
  rewriting legacy → canonical in history adds no value when the screen
  immediately resets to `Main`.
