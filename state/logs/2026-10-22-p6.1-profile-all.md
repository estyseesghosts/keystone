# 2026-10-22 — p6.1 profile All tab — subagent (Wave 1 §1.1)

Branch: `p6.1-profile-all`
Goal: restore v1's `All` profile tab (replies + renotes) beside Featured /
Posts / Replies / Media, with both server families able to express it.

Did:

- `packages/fedi/src/core/feedDescriptor.ts`: `UserFeedTab` and the
  `user|…|…` `FeedDescriptor` member gain `"all"`; `USER_TABS` includes it
  so parse/format/guard round-trip exactly.
- `src/state/queries/usePostFeedQuery.ts`: `case 'all'` dispatches
  `backend.accountPosts(id, {withReplies: true, withRenotes: true})`.
  Posts (`false/false`), Replies (`true/false`), Media
  (`withFiles: true, withRenotes: false`), Featured unchanged.
- `src/components/Profile/ProfileTabs.tsx`: label `All`, order becomes
  `featured, posts, all, replies, media`; Featured-hiding filter untouched.
  `User.tsx` default stays `posts` (no change needed).
- `packages/fedi/src/core/backend.ts`: `AccountPostsOpts` comment now names
  the All tab and the Mastodon cross-mapping.
- Tests:
  - `src/components/Profile/__tests__/profile.test.tsx` — 5-tab order with
    Featured, 4-tab order without it, `onChange('all')`.
  - `src/state/queries/usePostFeedQuery.test.tsx` — `all` → both flags true.
  - `src/state/queries/feeds.test.ts` — `profileTabDescriptor(…, 'all')`
    parses to `{kind: 'user', tab: 'all'}`.
  - `packages/fedi/test/feedDescriptor.test.ts` — `user|9abc|all` in the
    VALID parse/format/guard matrix.
  - `packages/fedi/test/mastodon-backend.test.ts` — pins the three wire
    queries: Posts `{exclude_replies: true, exclude_reblogs: true,
    limit: 20}`, Media `{only_media: true, limit: 20}`, All `{limit: 20}`.
  - `packages/fedi/test/misskey-backend.test.ts` — All sends
    `users/notes {userId, limit: 20, withReplies: true, withRenotes: true}`.

Decided (→ ADR or DECISIONS entry if load-bearing):

- No ADR: this is a plan-literal slice (clickstone §1.1), not a reversal.
- All remains a separate tab from Replies (v1 keeps both in the brief;
  clickstone says "Add `all` as a tab, keep Replies").
- Mastodon representation: `withReplies: true, withRenotes: true` resolves
  to no `exclude_replies` / `exclude_reblogs` params, which IS the server
  default (replies + boosts included). `resolveStatusFilters` drops
  explicit `false` filter values, so the wiring is correct without sending
  a field the contract does not define. No gating needed; both families
  express All.
- Misskey representation: `users/notes` already accepts both flags and the
  core option pass-through sends them verbatim (`withRenotes` defaults to
  true upstream, so it is sent explicitly — the existing Posts-tab rule).
