# 2026-10-25 — repair25-x3.3-paging — slice agent X3.3

Branch: working tree on `main` (no branch, no commit — coordinator owns commit)
Goal: repair25 §X3.3 — a failed page never causes a request loop; 429 is honoured.

## Did

Followed §X3.3 steps 1–4 exactly:

1. **New `src/state/queries/usePagedLoad.ts`** — `usePagedLoad(source)` returns an
   `onEndReached` that no-ops when `!hasNextPage || isFetchingNextPage ||
   isFetchNextPageError || coolingDown`, and latches with a ref until
   `isFetchingNextPage` goes true then false (burst events call once).
   Wired into both HomeFeed call sites (`handleScroll` proximity prefetch +
   `onEndReached`), Notifications, RecommendationsFeed, Conversations,
   ChatThread, and PostFeed.
2. **429 handling** — new `retryAfterMsOf(err)` in `src/state/queries/retry.ts`
   (reads parsed `retryAfterMs` from `ApiError.params`, 429-only). While the
   error flag holds, a 429 with a delay arms `coolingDown` until it elapses,
   with a visible countdown in the footer via `msg`/`plural`
   (`Auto-load paused by the server — resumes in # seconds.`). Only the
   explicit Retry button calls `fetchNextPage` directly and clears
   `isFetchNextPageError`; auto-paging never does.
3. **Pull-to-refresh trims to the first page** — `trimInfiniteDataToFirstPage`
   (pure) + `trimQueryToFirstPage` + `useRefreshFirstPage(queryKey, refetch)`;
   wired into HomeFeed, Notifications, RecommendationsFeed, Conversations
   refresh controls (`reload` too). ChatThread trims when its optional
   `queryKey` is present, else plain refetch.
4. **End heuristics documented** in the helper header (do-not-change): a feed
   ends only on `end: true` / no cursor / empty page; short pages never end a
   feed. No `getNextPageParam` touched.

Supporting changes inside listed files only:
- `ChatThreadData` gains optional `isFetchNextPageError` + `queryKey`;
  missing flag falls back to "error with loaded items" so current callers
  (`ChatRoom`/`ChatUser`, untouched — out of scope) are still guarded.
- `Conversations` and `ChatThread`: full error screen only when there is NO
  data; with data the list stays mounted with a footer Retry (was: any error
  nuked the loaded list — same class as Channels M3).
- `PostFeed` (test harness): new optional `isFetchNextPageError`/`moreError`
  props, error footer with Retry + countdown.
- New `testID`s for tests only: `notifications-list`, `conversations-list`,
  `${testPrefix}-list`.

## Decided

- Explicit Retry bypasses the 429 cooldown (tap always fetches; only
  auto-paging is suppressed). Logged here, no ADR (narrow UI behavior).
- 429 without parseable `retryAfterMs` → no timed cooldown, error guard only.
- `ChatRoom`/`ChatUser` passing `queryKey` + `isFetchNextPageError` explicitly
  is a one-line follow-up for the coordinator (files out of scope for X3.3);
  the fallback derivation covers them until then.
