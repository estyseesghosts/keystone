Decided (→ DECISIONS if load-bearing):

- Akkoma/Pleroma `poll[hide_totals]`: documented in their OpenAPI spec but
  never persisted by `make_poll_data/1`, so the capability is
  `unsupported` and Keystone does not send it. Sending it would have been
  accepted and silently ignored — worse than omitting. Not an ADR (no
  framework/data-model change); noted here and in the task file.
- Backend gating repeats the UI gating: `listFieldsBody` refuses to send a
  field whose capability is not `supported`, so a caller mistake can never
  put an unknown param on the wire.
- `hideTotals` is `true`-only on the wire (never `false`) so a server
  default is not overwritten; the capability gate drops it entirely
  elsewhere.
